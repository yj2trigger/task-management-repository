# 흰냥이 요구사항 정의 (아키텍처 설계 전)

> 목적: 아키텍처를 짜기 전에 "무엇을, 누가(우리 앱/Croche), 어느 수준까지, 어떻게 확인할지"를 고정한다. 신청서 3-3과 본선 시연의 근거 문서.
> 상태: 초안 v3 (2026-10-07). 디스코드 토의(역할 분담 표 + 피드백) 반영. 아키텍처 설계 0~1단계 결정을 §8에 기록하고 관련 섹션에 반영.
> 근거: 앱-생성-가이드.md, 신청서-초안.md, croche-조사.md, 아이디어.md, 해커톤 심사 기준, 디스코드 토의

## 0. 범위 원칙

### 0-1. 우선순위 표기

| 표기         | 뜻                                 | 신청서에서                     |
| ------------ | ---------------------------------- | ------------------------------ |
| **P0** | 3일 안에 만들고 데모에서 보여 준다 | "해커톤에서 구현"              |
| **P1** | P0가 끝나면 만든다                 | 언급하지 않거나 "여유 시 구현" |
| **P2** | 해커톤 이후                        | "확장 계획"으로만              |

본선에서는 심사위원이 팀을 돌며 실제 동작을 확인한다. 신청서에 "3일 구현"으로 적는 범위는 **P0와 같아야 한다**.

### 0-2. 판단 기준

- 심사 문구: "한 명의 사용자가 서비스를 열어서 핵심 경험을 끝까지 마치는 흐름이 실제로 동작하는지, AI가 없으면 안 되는 이유가 분명한지."
- 모든 요구사항은 §2 핵심 흐름 중 하나에 속해야 한다. 속하지 않으면 P2.
- 각 영역마다 **우리 앱이 하는 일 / Croche가 하는 일 / Croche 실패 시**를 적는다 (심사 ④).
- 시간은 모두 KST.

## 1. 역할 경계 (가장 먼저 고정할 것)

### 1-1. 원칙

> **캐릭터가 "언제, 어떤 선택지 안에서" 움직이고 말할지는 우리 앱이 데이터로 정하고, Croche는 "그 선택지 중 무엇을, 어떻게 말하며" 할지를 정한다.** (AD-07)

디스코드 토의 지적: 판단이 "프롬프트 유사도로 순위만 매기는" 수준이면, 캐릭터가 실제로 무엇을 할지는 결국 Croche(LLM)가 정하게 된다. 그러면 "판단은 규칙으로 → 데모가 매번 같게 나온다"는 의도와 모순된다. 그래서 판단 범위를 넓힌다.

| 구성요소                       | 담당    | 하는 일                                                                                                                                                                                            | 예                                                               |
| ------------------------------ | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 👀**관찰기**             | 우리 앱 | PC에서 일어난 일을 기록한다. 활성 창·입력·최근 파일을 직접 읽고, 드래그·쓰다듬기·대화 반응은 다른 구성요소에게 알림을 받아 기록 (§3.1)                                                        | "14:03 VS Code가 앞에 옴", "드래그로 치움"                       |
| 🧭**사용자 파악기**      | 우리 앱 | 기록을 보고 "지금 사용자가 어떤지"를 즉시 계산한다 (상황 태그·해석 상태, 메모리에서) (§3.16)                                                                                                     | "지금 바쁨 0.8, 귀찮아함 0.6, 하루 마감 중"                      |
| 🐾**움직임 결정기**      | 우리 앱 | **0층(매 순간).** 평상시 동작·이동 리듬·드래그·쓰다듬기 반응을 혼자 정한다. 다른 구성요소의 응답을 **절대 기다리지 않는다** (§3.7, §3.14, AD-18)                                  | "지금은 앉아 있자", "목적지는 활성 창 윗변"                      |
| ⏰**말 걸 때 판단기**    | 우리 앱 | **1층 입구(몇 초마다).** 지금 말을 걸어도 되는지만 판단한다 (상황 태그·해석 상태·성향·예산) (§3.15.3, §3.16)                                                                            | "회의 중이라 안 됨" / "지금 빈틈, 말 걸어도 됨"                  |
| 📋**선택지 메뉴 작성기** | 우리 앱 | **1층(말 걸 때만).** 행동+말 묶음 선택지 3~5개 + "말 안 걸기"를 점수·근거와 함께 만들고, 배경정보를 묶어 말 요청을 완성한다 (§3.5, §3.15.4, AD-07)                                        | "하루 회고 질문·수고 칭찬·말 안 걸기 중 골라 줘"               |
| 📈**학습기**             | 우리 앱 | 사용자 반응을 보고**오래 남는 값**을 고친다: 고양이 설정 값, 사용자 성향·친밀도, 선택지 상태·가중치. Croche의 수정 제안도 여기서 검사한 뒤에만 반영 (§3.9, §3.10, §3.14, §3.15, AD-09) | "VS Code 오른쪽 위 선호 −0.3", "단답형 → 선택지형 가중치 +0.1" |
| 🐟**먹이 창고**          | 우리 앱 | 먹인 자료와 일정을 정리하고,**질문·상황에 맞는 참고 자료를 골라 준다** (§3.3, §3.4, §3.6)                                                                                                | "정규화 질문이면 정규화.pdf", "10/12 17시 마감"                  |
| 🗺**길 찾기**            | 우리 앱 | 밟을 곳을 찾고 목적지까지 가는 길을 만든다 (§3.8)                                                                                                                                                 | "탭 윗변 → 점프 → 창 윗변"                                     |
| 💬**대화 관리자**        | 우리 앱 | 대화를 이어 가고 끝낸다. 대화 내역 저장 (§3.15)                                                                                                                                                   | 단답 2번이면 "이따 얘기하자냥"                                   |
| 🔌**Croche 연결기**      | 우리 앱 | 우리 형식(§1-2)을 Croche에 맞게 바꿔 보내고 받는다. Croche를 부르는 유일한 곳 (AD-11)                                                                                                             | 메뉴를 보내고 "b번, 이 문장으로"를 받음                          |
| 🐱**고양이 화면**        | 우리 앱 | 고양이를 그리고, 걷게 하고, 말풍선을 띄우고, 클릭·드래그를 받는다. 파일 열기·휴식 화면 실행                                                                                                      | 걷는 애니메이션, 목덜미 들림                                     |
| 📊**적응 대시보드**      | 우리 앱 | 학습 결과를 한 화면에 보여 준다 (US-06)                                                                                                                                                            | 데모 때 옆에 띄움                                                |
| 🗄**저장소**             | 우리 앱 | 모든 데이터를 DB에 넣고 꺼낸다 (AD-01)                                                                                                                                                             | —                                                               |
| 🎯**선택과 말**          | Croche  | 1층 메뉴에서**하나를 고르고**(도구 호출 형태), 문장을 고르고 말투를 입힌다 (§3.9, AD-07)                                                                                                    | "b번. '오늘 3시간 집중했네! 대단해냥'"                           |
| 🧠**LLM이 필요한 일**    | Croche  | 자료 요약·태그 뽑기, 날짜 표현 찾기, 질문 답하기, 자연어 피드백 해석, 말투·행동·가중치 수정**제안**(반영은 학습기)                                                                        | "이 PDF 주제는 SQLD 정규화"                                      |

판단을 우리 앱에 둔 이유: 데모가 매번 같게 나와 안정적이다 · LLM 호출이 줄어 비용이 준다 · "왜 이걸 추천했는지" 근거를 보여 줄 수 있다.

### 1-2. 우리 앱 ↔ Croche 주고받는 형식 (P0)

경계가 흐려지지 않도록 **Croche에 넘기는 것과 받는 것의 모양을 고정**한다. Croche는 이 안에서만 결정한다.

**말 요청 (우리 앱 → Croche)**

| 필드                | 뜻                                                                                                                                                                 | 예                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `intent`          | 말의 의도 (우리 앱이 정함, enum)                                                                                                                                   | `recommend` `schedule_notice` `praise_request` `accept_refusal` `break` `answer` `greet` `chat` `chat_open` `followup` `name_prank` |
| `facts`           | 반드시 사실대로 써야 할 내용                                                                                                                                       | `{food_title:"정규화.pdf", days_left:1, reasons:["집중 시간대", "5일째 안 봄"]}`                                                                        |
| `refs`            | 참고 자료 (우리 앱이 고름)                                                                                                                                         | `[{food_id:12, title, excerpt}]`                                                                                                                        |
| `context`         | 배경정보 묶음 (§3.5)                                                                                                                                              | 활성 창, 관련 일정, 최근 대화                                                                                                                             |
| `voice`           | 현재 말투 프로필 (§3.9)                                                                                                                                           | —                                                                                                                                                        |
| `constraints`     | 지켜야 할 조건                                                                                                                                                     | `{max_sentences:1, must_include:["정규화"]}`                                                                                                            |
| `allowed_actions` | 붙여도 되는 버튼·행동 (우리 앱이 정함)                                                                                                                            | `["open_file:12", "later"]`                                                                                                                             |
| `options[]`       | 1층 선택지 메뉴 (말 걸 기회일 때). 항목마다`id`, 소재, 말 거는 방법, `pose`, `move_to`, 버튼, 점수, 근거. **"말 안 걸기"(`none`)를 늘 포함** (AD-07) | `[{id:"a", topic:"하루 회고", opener:"question", pose:"sit_look", score:0.82, reason:["하루 마감 중"]}, …, {id:"none"}]`                               |
| `user_state`      | 사용자 상태 요약 (§3.16)                                                                                                                                          | 상황 태그, 해석 상태, 성향, 친밀도                                                                                                                        |
| `cat_memo`        | 고양이 메모 (칸이 정해진 텍스트, AD-06)                                                                                                                            | 최대 10줄                                                                                                                                                 |

**말 응답 (Croche → 우리 앱)**

| 필드             | 뜻                                     | 우리 앱의 검증                                                      |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------- |
| `choice_id`    | 고른 선택지 (`options`가 있었을 때)  | 메뉴 안의 id인지. 밖이면 점수 1등을 실행                            |
| `text`         | 말풍선 문장 (`none`을 골랐으면 비움) | 길이,`must_include` 포함 여부, 금지 표현                          |
| `emotion`      | 감정 1개 (enum)                        | enum 밖이면`happy`로                                              |
| `action`       | `allowed_actions` 중 하나 또는 없음  | 목록 밖이면 버림                                                    |
| `variant`      | 세부 동작 변형 (§3.10)                | 해당 동작의 변형 목록 안인지                                        |
| `voice_patch`  | 말투 수정 제안 (선택)                  | 범위·하루 변경 한도 (§3.9)                                        |
| `motion_patch` | 이동 리듬 수정 제안 (선택)             | 범위·하루 변경 한도 (§3.14)                                       |
| `user_mood`    | 사용자 답의 감정 (대화 중일 때)        | `positive` `neutral` `negative` 밖이면 `neutral` (§3.15.6) |

검증 실패 시: 1회 재요청 → 또 실패하면 템플릿 문장 (§3.11).

| 1    | 앱을 켠다                                        | 작업표시줄·창 위에 내려앉아 걷는다                                | 발판 계산·이동                                  | —                                    |

## 3. 기능 요구사항

### 3.1 감각: 관찰자 (SN)

| ID    | 우선 | 요구사항                                                                                                           | 어디에 쓰나                                          |
| ----- | ---- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| SN-01 | P0   | 활성 창의 제목·앱 이름·창 위치를 1초마다 읽는다                                                                  | 자료 선택 맥락(§3.4), 이동 목적지(§3.7), 앱별 시간 |
| SN-02 | P0   | **입력 활동은 분 단위 "활동 중/쉬는 중"과 강도 3단계(없음·보통·많음)만 기록한다.** 키 값은 받자마자 버린다 | 아래 표                                              |
| SN-03 | P0   | 최근 연 파일(Windows 최근 항목)의 이름·경로·시각                                                                 | 먹인 자료의`last_opened` 갱신 → 추천 점수         |
| SN-04 | P1   | 브라우저 주소                                                                                                      | 먹인 링크의`last_opened`                           |

**입력 활동을 쓰는 곳** (디스코드 질문 "입력 횟수를 어디에 쓰나"에 대한 답)

| 쓰는 곳                                                                   | 필요한 정보          |
| ------------------------------------------------------------------------- | -------------------- |
| 90분 연속 작업 → 휴식 권유 (RC-03)                                       | 분 단위 활동 중 여부 |
| 자리 비움 감지 (5분 무입력) → 말 걸지 않음, 돌아오면 "왔어?"             | 마지막 입력 시각     |
| 말 걸 타이밍: 입력이 활발하다 멈춘 직후 = 작업 사이 빈틈 (RT-07)          | 분 단위 강도 변화    |
| 행동 선택: 타이핑 중엔 조용한 동작, 쉬는 중엔 활발한 동작 (§3.7)         | 현재 강도            |
| 집중 시간대 통계: 시간대별 "활동 중" 분 합계 → "넌 10시에 제일 잘하잖아" | 분 단위 기록         |

정확한 횟수는 쓰지 않는다. 강도 3단계 구분에만 분당 횟수를 잠깐 센다.

### 3.2 저장: 무엇을 어디에 (DS)

디스코드 지적: PDF·프롬프트 내역·여러 파일 등 저장할 데이터가 많아 Croche 저장소로는 부족하다. → **원칙: 코드가 조건으로 찾아야 하거나 큰 데이터는 우리 앱(로컬 DB), Croche에는 "말할 때 기억해야 할 짧은 사실"만.**

| ID    | 우선 | 요구사항                                                                            |
| ----- | ---- | ----------------------------------------------------------------------------------- |
| DS-01 | P0   | 아래 표대로 저장 위치를 고정한다                                                    |
| DS-02 | P0   | Croche 기억에 넣는 항목은 한 줄 문장, 개수 상한(예: 50개)을 두고 오래된 것부터 정리 |
| DS-03 | P0   | 로컬 DB가 기준 원본이다. Croche 기억이 지워져도 로컬 DB로 다시 만들 수 있어야 한다  |

| 데이터                 | 저장 위치               | 형태                                            | 누가 쓰나                      |
| ---------------------- | ----------------------- | ----------------------------------------------- | ------------------------------ |
| 원본 파일              | 사용자 PC (경로만 저장) | 경로                                            | 실행(열기)                     |
| 추출한 본문            | 로컬 DB                 | 문단 단위 조각 + 전문 검색 색인                 | 자료 선택(§3.4), 답할 때 발췌 |
| 먹이 메타데이터        | 로컬 DB                 | `food` (§3.3)                                | 추천·자료 선택                |
| 일정·할 일            | 로컬 DB                 | `schedule` (§3.6)                            | 안내·추천                     |
| 대화·프롬프트 내역    | 로컬 DB                 | 시각·발화자·문장·의도·참고 자료             | 최근 대화 묶기(§3.5), 일기    |

### 3.3 먹이 수집·구조화 (FD)

목표: 먹인 자료를 **나중에 코드가 조건으로 찾을 수 있는 형태**로 저장한다. 스키마와 저장은 우리 앱, 자유 형식 글에서 의미를 뽑는 부분만 Croche(LLM)가 맡는다.

| ID    | 우선 | 요구사항                                                                                                                                                  |
| ----- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FD-01 | P0   | 입력 경로 3가지: 파일 드롭, 링크 드롭(또는 붙여넣기), 말풍선 한 줄 텍스트                                                                                 |
| FD-02 | P0   | 지원 형식:`.pdf`(텍스트 있는 것) `.txt` `.md`, 링크(페이지 제목·설명). `.docx` `.pptx`는 P1(§6-5). 글자를 못 뽑으면 "무슨 자료야?" 한 줄 질문 |
| FD-03 | P0   | **우리 앱이 하는 구조화**: 본문 추출, 문단 조각 나누기, 전문 검색 색인, 자주 나온 단어 상위 20개(빈도 기준)                                         |
| FD-04 | P0   | **Croche에 맡기는 구조화**: 파일명 + 본문 앞 6,000자 + 빈도 단어 → 아래 스키마의 JSON (먹이당 1회). 스키마 밖 필드는 버린다                        |
| FD-05 | P0   | 주제 태그는 기존 태그 목록을 함께 보내**그 안에서 먼저 고르게** 한다 (태그 갈라짐 방지)                                                             |
| FD-06 | P0   | 확신도 낮은 필드 하나만 되묻는다. 먹이당 최대 1질문                                                                                                       |
| FD-07 | P0   | 먹은 것 수첩: 목록, 태그·사용 조건 수정, 삭제                                                                                                            |
| FD-08 | P1   | 중복 감지 (같은 경로·같은 내용 해시)                                                                                                                     |
| FD-09 | P2   | 폴더 통째로 먹이기, 이미지 글자 인식                                                                                                                      |

**먹이 스키마 (`food`)**

| 필드                                                           | 채우는 쪽                          | 예                                                                    |
| -------------------------------------------------------------- | ---------------------------------- | --------------------------------------------------------------------- |
| `id`, `kind`, `path_or_url`, `fed_at`, `last_opened` | 우리 앱                            | `file`, `C:\…\정규화.pdf`                                        |
| `title`                                                      | 우리 앱(파일명) → Croche가 다듬음 | "SQLD 정규화 정리"                                                    |
| `summary`                                                    | Croche                             | 2문장                                                                 |
| `topics[]`                                                   | Croche (기존 태그 우선)            | `["SQLD", "데이터베이스"]`                                          |
| `keywords[]`                                                 | 우리 앱(빈도) + Croche(보완)       | `["정규화", "제2정규형", "함수 종속"]`                              |
| `doc_type`                                                   | Croche (enum)                      | `study` / `notice` / `reference` / `todo`                     |
| `difficulty` (1~3), `est_minutes`                          | Croche                             | 2, 20                                                                 |
| `use_when.context_keywords[]`                                | Croche                             | `["SQL", "DBeaver", "ERD"]` — 활성 창 제목·앱 이름과 맞춰 볼 단어 |

| `use_when.schedule_ids[]`                                    | 우리 앱 (§3.6 연결)               | —                                                                    |
| `confidence`                                                 | Croche                             | 필드별 0~1                                                            |

| Croche 실패 시                                                            |
| ------------------------------------------------------------------------- |

### 3.4 참고 자료 고르기: 관련도 측정 (RT)

목표: "이 질문(또는 이 상황)은 a, b, c 자료를 참고해야 한다"를 **우리 앱이 정한다.** Croche는 고른 자료를 받아 답할 뿐 고르지 않는다.

| ID    | 우선 | 요구사항                                                                                                                                                                                                                                                                       |
| ----- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| RT-01 | P0   | **의도 분류 (우리 앱 규칙)**: `schedule_query` / `find_doc` / `ask_about_doc` / `action` / `chat`. 규칙: "언제·마감·일정·D-" → 일정, "열어·찾아·어딨" → 자료 찾기, 먹이 제목·키워드가 문장에 있음 → 자료 관련, "쉬자·타이머" → 행동, 나머지 → 잡담 |
| RT-02 | P1   | 규칙에 안 걸리고 문장이 질문형이면 Croche에 의도 분류만 요청 (enum 응답)                                                                                                                                                                                                       |
| RT-03 | P0   | **관련도 점수 (우리 앱)** = 전문 검색 점수(BM25) + 주제 태그 일치 + 활성 창과 `context_keywords` 일치 + 연결 일정 마감 임박 − 최근 거절 − 오늘 이미 연 것. 가중치는 설정 파일 하나에 둔다                                                                            |
| RT-04 | P0   | **선택 규칙**: 기준점 이상인 상위 최대 3개 = 참고 자료. 1등이 2등보다 크게 높으면 1개만. 기준점 이상이 없으면 "없음"                                                                                                                                                     |
| RT-05 | P0   | `ask_about_doc`이면 고른 자료 안에서 질문과 가장 관련 있는 문단 3개를 발췌해 `refs`로 넘긴다                                                                                                                                                                               |
| RT-06 | P0   | "없음"이면 Croche에 의도`answer` + `facts:{found:false}`로 넘겨 "그건 아직 안 먹었어. 먹여 줄래?"를 말하게 한다 (지어내지 않음, 심사 ④)                                                                                                                                   |
| RT-07 | P0   | **선제 추천 트리거**: 아침 첫 입력, 휴식 끝, 활발한 입력이 멈춘 직후, 활성 창이 어떤 먹이의 `context_keywords`와 처음 일치할 때 → 추천기(RC-01)가 1등 1개                                                                                                             |
| RT-08 | P0   | 같은 자료를 같은 트리거로 하루 2번 이상 꺼내지 않는다                                                                                                                                                                                                                          |
| RT-09 | P0   | 선택 근거(점수 항목)를 로그에 남기고 수첩에서 볼 수 있다 ("왜 이걸 추천했어?")                                                                                                                                                                                                 |
| RT-10 | P2   | 의미 기반 검색(임베딩)으로 동의어 보완                                                                                                                                                                                                                                         |

**수용 기준:** "정규화 자료 어딨지?" → 5초 안에 [열기] 버튼 / "SQLD 언제야?" → 일정 답 / DBeaver 창을 열면 30초 안에 정규화 자료 제안(하루 1번) / 먹이지 않은 주제 질문 → "아직 안 먹었어".

### 3.6 일정·할 일 분류 (SC)

목표: 먹이에 들어 있는 마감·실행 시점을 따로 뽑아, **캘린더·할 일 목록·주간 일정표 어느 쪽으로도 바꾸기 쉬운 형태**로 저장하고, 알맞은 때 안내한다.

| SC-02 | P0   | 출처: 한 줄 입력, 문서 본문(공지 PDF의 "제출기한 10/12 17:00"), 파일명                                                                                                                 |
| SC-03 | P0   | Croche가 날짜 표현 찾기 → `[{type, 원문 구절, 날짜, 시각                                                                                                                              |
| SC-04 | P0   | 우리 앱 정규화: 상대 날짜("다음 주 금요일")는 먹인 날짜 기준 절대 날짜로, 연도가 없으면 가장 가까운 미래, 지난 날짜면 표시하고 묻는다.**날짜 계산은 LLM에 맡기지 않는다**        |

| SC-08 | P0   | 보기 3가지 (같은 데이터를 다르게 조회): 오늘 할 일 목록 / 이번 주 일정표(요일별) / 다가오는 마감                                                                                       |

### 3.7 큰 틀의 캐릭터 행동 결정 (BH)

목표: 매 순간 고양이가 **이동할지, 어떤 동작을 할지, 말풍선을 띄울지·어디에, 무슨 의도로 말할지**를 우리 앱이 정한다. 결과는 "행동 계획" 한 개로 만든다.

**행동 계획 (우리 앱 내부 형식)**

| 필드         | 뜻                              | 예                                                                                                                                                                                         |
| ------------ | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `move_to`  | 이동 목적지                     | `none` / `active_window_top` / `taskbar` / `nearest`                                                                                                                               |
| `pose`     | 큰 동작 (enum)                  | `idle` `walk` `sit_look` `sleep` `eat` `stretch` `beg_praise` `happy` `sad` `think` `lifted`(들림) `fall`(낙하) `hide`(숨기·흐려지기) `float`(둥실, 유령냥이) |
| `bubble`   | 말풍선 표시 여부·위치          | `{show:true, anchor:"above"}`                                                                                                                                                            |
| `speech`   | 말 요청의`intent` + `facts` | §1-2                                                                                                                                                                                      |
| `buttons`  | 붙일 버튼                       | `[open_file:12, later]`                                                                                                                                                                  |
| `priority` | 겹칠 때 무엇이 이기나           | 사용자 조작(드래그·클릭·메뉴) > 사용자 질문 답 > 건강 > 일정 > 추천 > 잡담·이어 가기 > 장난(이름·투명도) > 평상시 동작                                                                 |

| ID    | 우선 | 요구사항                                                                                                                                                                      |
| ----- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BH-01 | P0   | 이벤트 → 행동 계획 규칙을 아래 표로 고정한다                                                                                                                                 |
| BH-02 | P0   | 동시에 여러 이벤트가 생기면`priority`가 높은 하나만 실행, 나머지는 대기열 (최대 3개, 10분 지나면 버림)                                                                      |
| BH-03 | P0   | 말을 걸 때는 먼저 이동 → 도착 후`sit_look` → 말풍선 (걸어와서 말 거는 연출)                                                                                               |
| BH-04 | P0   | **말풍선 위치**: 고양이 위가 기본. 위쪽 공간이 부족하면 아래, 화면 좌우 끝이면 안쪽으로 밀기. 활성 창의 입력 중인 영역은 가리지 않도록 고양이 쪽을 창 밖으로            |
| BH-05 | P0   | 말풍선 유지: 버튼이 있으면 60초, 없으면 8초. 60초 무응답 = 무응답 기록                                                                                                        |
| BH-06 | P0   | 이벤트가 없을 때 평상시 동작: 가중 랜덤(걷기·앉기·그루밍·자기) + 시간대(밤엔 자기 ↑) + 입력 강도(많음이면 조용히, 없음이면 활발히). 가중치는 행동 패턴(§3.10)에서 읽는다 |
| BH-07 | P0   | `proactive_per_hour` 상한·조용 시간대·자리 비움·전체화면이면 먼저 말 걸기를 미룬다                                                                                       |

**이벤트 → 행동 계획**

| 이벤트                                                    | move_to                                        | pose                                               | bubble                                  | intent                       | buttons                             |
| --------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------- | --------------------------------------- | ---------------------------- | ----------------------------------- |
| 먹이 드롭                                                 | `none`                                       | `eat`                                            | ● (템플릿)                             | —                           | —                                  |
| 구조화 확인 필요                                          | `none`                                       | `sit_look`                                       | ●                                      | `chat`(질문)               | [맞아] [고칠래]                     |
| 선제 추천                                                 | `active_window_top`                          | `sit_look`                                       | ●                                      | `recommend`                | [열기] [나중에]                     |
| 일정 안내                                                 | `active_window_top`                          | `sit_look`                                       | ●                                      | `schedule_notice`          | [끝냈어] [미뤄 줘]                  |
| 90분 연속 작업                                            | `active_window_top`                          | `stretch`                                        | ●                                      | `break`                    | [같이 쉬기] [10분만]                |

### 3.8 화면 위 이동 (WK)

목표: **어떤 앱·웹사이트에서든** 사람이 봤을 때 "고양이가 밟고 설 수 있겠다" 싶은 곳(창 윗변, 강조된 탭, 버튼·배너·이미지·카드의 윗변 등)을 찾아 그 위로 다닌다. **전부 우리 앱, Croche 관여 없음** (비용 0). Croche는 이동을 정하지 않는다 — 목적지는 행동 계획(§3.7)이 정한다.

#### 발판을 찾는 3개 층

특정 앱(VS Code 등)에 맞춘 규칙은 만들지 않는다. 앱 종류와 무관하게 동작하는 층을 겹쳐 쓴다. **창 발판이 기본, 화면 선 발판이 "어느 앱이든 화면 속 선·면 위를 걷게" 하는 주력, 요소 정보 보강은 의미(선택된 탭·버튼)를 보강**한다 (AD-25).

| WK-22  | P1 | 요소 정보 보강 조회가 1초를 넘으면 그 앱은 다음부터 조회 범위를 줄인다(창 위쪽 절반만 등) 또는 그 앱에선 화면 선 발판만 쓴다 |
| WK-23  | **P0 후반** | **화면 선 발판**: 모든 앱에 적용. 화면이 바뀌었을 때만(작은 썸네일 비교), 최대 1초에 1번, 절반 축소 흑백. 캡처한 이미지는 메모리에서만 처리하고 저장하거나 Croche에 보내지 않는다(비용 0) |
| WK-23a | P0 후반 | 캡처에서 **고양이·말풍선 창 영역을 지우고** 분석 (자기 자신을 발판으로 잡지 않게) |
| WK-23b | P0 후반 | **안정화**: 2~3번 연속 같은 자리(±3px)에 나온 선분만 발판으로 인정 (영상·애니메이션·스크롤 중 깜빡임 방지) |
| WK-23c | P1 | 어두운 테마·고배율(DPI)·영상 재생 화면에서 기준값 점검, 앱별 기준값 학습 |
| WK-24  | P1           | **스크롤·화면 변화**: 서 있던 발판이 40px 이하로 움직이면 같이 움직인다(타고 감). 더 크게 움직이거나 사라지면 낙하(WK-09)                                                       |
| WK-25  | P1           | 층을 합칠 때 같은 위치(±5px)의 선분은 하나로 합친다                                                                                                                                   |
| WK-26  | P2           | 앱별로 잘 맞은 발판 종류를 기억해 다음 조회를 빠르게                                                                                                                                   |

**축소안:** 요소 정보 보강·화면 선 발판을 빼고 창 발판만 쓴다(데모는 유지). 그보다 더 밀리면 WK-03·WK-08 경로 탐색도 빼고 "작업표시줄 + 활성 창 윗변"만, 목적지까지 점프 한 번.

**수용 기준:**

- P0: 창 3개가 겹친 상태에서 보이는 윗변 위로만 걷는다. 추천 이벤트 때 활성 창 윗변까지 걸어가 앉는다. 밟고 있던 창을 닫으면 떨어져 착지한다.
- P1: 브라우저에서 웹페이지(예: croche.ai)의 버튼·이미지·배너 윗변 위를 걷는다. VS Code에서 선택된 탭 위에 앉는다. 탭 정보를 주지 않는 앱에서도 화면 선 발판으로 상자 윗변을 찾는다. 웹페이지를 스크롤하면 발판을 따라 움직이거나 떨어진다.

**위험:** 요소 정보 보강·화면 선 발판은 Windows API와 이미지 처리가 필요하다. JS(Electron)에서 직접 부르기 어려우면 좌표를 JSON으로 내보내는 작은 보조 프로그램(C# 등)을 둔다 → §6-1 언어 결정에 포함.

### 3.9 말투: 저장·사용·적응·초기 랜덤성 (VC)

목표: 말투를 **정해진 모양의 프로필**로 저장하고, 매 말 요청에 첨부해 Croche가 그 프로필대로 말하게 한다. 프로필 수정은 Croche가 사용자 데이터를 보고 제안하고, 우리 앱이 범위를 확인해 적용한다.

**말투 프로필 (`voice`)**

| 필드                        | 범위         | 기본 / 초기값                | 예                         |
| --------------------------- | ------------ | ---------------------------- | -------------------------- |
| `core` 고정 성격          | 변경 불가    | 가이드 §8-1                 | —                         |
| `length` 말 길이          | 1~2문장      | 1                            | —                         |
| `nyang` "냥" 빈도         | 0~2          | 랜덤                         | 0 안 씀 / 1 가끔 / 2 자주  |
| `aegyo` 애교 강도         | 1~3          | 랜덤                         | —                         |
| `call_user` 사용자 호칭   | 문자열       | 첫 실행 때 질문              | "집사", 이름               |
| `endings[]` 말끝 습관     | 최대 3개     | 풀에서 랜덤 2개              | "~하자", "~했지?", "~거든" |
| `catchphrases[]` 입버릇   | 최대 5개     | 풀에서 랜덤 3개              | "흐음", "냠", "나 천재지?" |
| `banned[]` 쓰지 않을 표현 | 목록         | 비난·죄책감·의학 진단 표현 | —                         |
| `examples[]` 말투 예시    | 상황별 2~3개 | 예시 묶음에서 현재 값에 맞게 | —                         |

| ID    | 우선 | 요구사항                                                                                                                                                                                                                                   |
| ----- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| VC-01 | P0   | **초기 랜덤성**: 첫 실행 때 `nyang`·`aegyo`를 범위 안에서 무작위로, `endings`·`catchphrases`를 미리 만든 풀(각 10~15개)에서 무작위로 골라 저장. 같은 앱이라도 사람마다 조금 다른 고양이. 시드를 저장해 데모 때는 고정 가능 |
| VC-02 | P0   | **예시 묶음**: 상황 6개(인사·추천·칭찬 조르기·거절 받아들이기·휴식 권유·일정 안내) × 애교 3단계 × 2~3문장 ≈ 40문장을 미리 손으로 쓴다                                                                                        |
| VC-03 | P0   | **사용**: 매 말 요청(§1-2)에 `voice` 전체 + 현재 상황의 예시 3개를 첨부. Croche는 `facts`를 바꾸지 않고 이 말투로 문장을 만든다                                                                                                 |

| VC-05 | P0   | **하루 단위 적응**: 하루 1번(하루 마감 또는 다음 날 첫 실행) 우리 앱이 반응 통계(쓰다듬기 수, 대답한 말 vs 무시한 말의 특징, 자주 쓴 입버릇)를 Croche에 보내고, Croche가 `voice_patch`를 제안                                      |
| VC-06 | P0   | **변경 한도**: 하루에 바뀌는 필드는 최대 2개, 숫자 값은 한 단계씩. `core`·`banned`는 바뀌지 않음                                                                                                                                |
| VC-07 | P0   | 변경 기록을 저장하고 수첩에서 고양이 말투로 보여 준다 ("요즘 너 냥을 좋아하는 것 같아서 더 써 볼게")                                                                                                                                       |

#### 고양이 자신의 이름과 이름 장난 (VC-N)

목표: 고양이에게 **본래 이름**이 있고, 말풍선에 그 이름이 표시된다. 대화 중에 고양이가 **표시 이름을 바꾸며 장난을 친다** ("천재냥이", "삐진냥이"). 사용자가 붙여 준 별명도 기억한다.

**이름 프로필 (`name`, `voice` 안에 둠)**

| 필드               | 뜻                                                   | 기본 / 예                                       |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------- |
| `base`           | 본래 이름                                            | "흰냥이" (첫 실행 때 사용자가 바꿀 수 있음)     |
| `display`        | 지금 말풍선에 보이는 이름                            | 평소엔`base`                                  |
| `nicknames[]`    | 사용자가 붙여 준 별명 (최대 5개)                     | "냥냥이", "흰둥이"                              |
| `liked_pranks[]` | 사용자가 [그 이름 좋아]를 누른 장난 이름 (최대 10개) | "천재냥이"                                      |
| `prank`          | 진행 중인 장난                                       | `{name, reason, started_at, until}` 또는 없음 |
| `prank_rate`     | 장난 빈도                                            | 0(안 함) ~ 3, 초기값은 VC-01 시드로 랜덤 1~2    |

**말풍선 표시:** 머리줄에 `display`를 쓴다. 장난 중이면 작게 본래 이름을 같이 쓴다 → `천재냥이 (원래 흰냥이)`. 사용자가 헷갈리지 않게 하기 위해서다.

**장난 패턴 (계기 → 이름 → 대사 예)**

| 패턴         | 계기 (우리 앱이 판단)                           | 장난 이름 예                     | 대사 예                                                      | 끝나는 때                      |
| ------------ | ----------------------------------------------- | -------------------------------- | ------------------------------------------------------------ | ------------------------------ |
| 자랑형       | 칭찬(쓰다듬기)을 연속 3번 받음                  | 천재냥이, 칭찬받는냥             | "오늘부터 나 천재냥이야. 불러 봐"                            | 1시간 뒤                       |
| 삐짐형       | 제안 거절 2번 연속                              | 삐진냥이                         | "…삐진냥이야. 말 걸지 마. (10초 뒤) 거짓말이야"             | 다음 수락 또는 쓰다듬기        |
| 먹이형       | 먹이를 먹은 직후 (그 날 첫 먹이)                | 정규화냥이 (먹은 자료 주제 + 냥) | "정규화 먹었더니 정규화냥이 됐어"                            | 그 날 끝                       |
| 배고픔형     | 3일 넘게 먹이를 안 줌                           | 배고픈냥이                       | "이름이 바뀌었어. 배고픈냥이야"                              | 먹이를 받으면                  |
| 시간대형     | 자정 넘어 작업 중                               | 야행성냥이, 수상한 고양이        | "이 시간엔 수상한 고양이로 변신해"                           | 아침 첫 입력                   |
| 박사형       | 자료로 질문에 답함                              | 냥냥박사                         | "냥냥박사가 알려 줄게"                                       | 대화가 끝나면                  |
| 별명 반응형  | 사용자가 대화에서 다른 이름으로 부름 ("흰둥아") | (사용자가 부른 이름)             | "나 흰냥인데? …흰둥이도 나쁘지 않네" → 별명 저장 여부 묻기 | — (별명은 저장)               |
| 이름 잊은 척 | 하루 1번 이하, 아침 인사 때 낮은 확률           | ??? 냥                           | "내 이름이 뭐였더라? 맞혀 봐" [흰냥이] [모르겠어]            | 사용자가 맞히면 "역시 날 알아" |

| ID     | 우선 | 요구사항                                                                                                                                                                                                               |
| ------ | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VC-N1  | P0   | 이름 프로필 저장, 말풍선 머리줄에`display` 표시, 첫 실행 때 이름 정하기 ("내 이름은 흰냥이야. 다르게 부르고 싶어?")                                                                                                  |
| VC-N2  | P0   | **계기 판단과 빈도는 우리 앱**: 위 표의 계기가 생기면 `prank_rate`에 따라 장난 여부를 정한다. 하루 최대 `prank_rate`번, 장난은 동시에 하나만, 건강·일정 안내 중에는 하지 않음(§3.7 우선순위)               |
| VC-N3  | P0   | **이름과 대사는 Croche**: 말 요청에 `intent: name_prank` + `facts:{pattern, base, 먹은 주제 등}`를 넘기면, Croche가 장난 이름 후보 1개와 대사를 만든다                                                       |
| VC-N4  | P0   | **검증 (우리 앱)**: 장난 이름은 10자 이하, 본래 이름의 일부나 "냥"을 포함하거나 위 표의 고정 이름 중 하나, 금지 표현 없음. 실패하면 표의 예시 이름을 쓴다                                                        |
| VC-N5  | P0   | 장난 이름 옆에 버튼: [원래대로] [그 이름 좋아]. [원래대로] → 즉시`base`로 돌아가고 "알았어, 흰냥이 할게". [그 이름 좋아] → `liked_pranks`에 저장                                                                 |
| VC-N6  | P0   | 끝나는 때(표의 마지막 열)가 되면 자동으로`base`로 돌아오고, 한 줄로 알린다 ("천재냥이 끝. 다시 흰냥이")                                                                                                              |
| VC-N7  | P0   | **적응**: [원래대로]가 3번 쌓이면 `prank_rate` −1, [그 이름 좋아]가 3번이면 +1 (범위 0~3). 그 장난 이름을 좋아한 패턴은 다음에 우선. `prank_rate`가 0이면 장난을 안 하고 수첩에 "이름 장난 그만했어"로 기록 |
| VC-N8  | P0   | 별명 반응형: 사용자 문장에서 고양이를 부르는 다른 이름을 찾으면(우리 앱: 문장 맨 앞 호격 "~아/야" 규칙 → 애매하면 Croche) 별명 저장 여부를 묻고, 저장한 별명은 장난 이름 후보로도 쓴다                                |
| VC-N9  | P1   | 이름 잊은 척 패턴 (맞히기 버튼)                                                                                                                                                                                        |
| VC-N10 | P1   | 사용자가`liked_pranks` 중 하나를 본래 이름으로 바꿀 수 있게 수첩에서 선택                                                                                                                                            |
| VC-N11 | P2   | 레벨에 따라 새 장난 패턴 해금                                                                                                                                                                                          |

**데모에 넣는 자리:** §2 흐름 7단계(쓰다듬기) 뒤 → 자랑형 "오늘부터 나 천재냥이야" + 머리줄이 `천재냥이 (원래 흰냥이)`로 바뀜 → [원래대로]를 누르면 돌아옴. 고양이가 "살아 있다"는 인상을 주는 짧은 장면이며, 계기와 빈도는 우리 앱이 정하므로 데모마다 같게 재현된다(심사 ③).

| 우리 앱                                                                                             | Croche                                                                   | Croche 실패 시                                            |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| 프로필 저장, 초기 랜덤, 예시 고르기, 반응 통계, 범위·한도 검사, 이름 장난의 계기·빈도·종료·검증 | 프로필대로 문장 만들기, 피드백·통계 → 수정 제안, 장난 이름 후보와 대사 | 템플릿 문장, 프로필 변경 없음, 장난 이름은 표의 예시 이름 |

### 3.10 세부 행동 패턴: 저장·수정 (BP)

목표: 큰 동작(§3.7 `pose`)은 우리 앱이 정하고, **그 안의 변형**(어떻게 칭찬을 조르는지, 어떤 식으로 노는지)은 프로필로 저장해 사용자 반응에 맞춰 바꾼다.

**행동 패턴 (`behavior`)**

| 큰 동작        | 변형 (가중치)                                       | 예                    |
| -------------- | --------------------------------------------------- | --------------------- |
| `beg_praise` | 꼬리 흔들기 / 머리 비비기 / 배 보이기 / 앞발로 톡톡 | 0.4 / 0.3 / 0.2 / 0.1 |
| `happy`      | 골골 / 하트 / 빙글                                  | —                    |
| `idle`       | 그루밍 / 하품 / 꼬리 말기 / 두리번                  | —                    |
| `sad`        | 귀 접기 / 등 돌리기                                 | —                    |
| 평상시 루틴    | 시간대별`walk`·`sit`·`sleep` 비율           | 오전 활발, 밤 졸림    |

| ID    | 우선 | 요구사항                                                                                                        |
| ----- | ---- | --------------------------------------------------------------------------------------------------------------- |
| BP-01 | P0   | 위 표 형태로 저장. 초기 가중치는 VC-01과 같은 시드로 약간 랜덤                                                  |
| BP-02 | P0   | 변형 선택: 우리 앱이 가중치로 고르거나, 말 응답의`variant`를 쓴다(목록 안일 때만)                             |
| BP-03 | P0   | 반응 기록: 변형별로 그 뒤 쓰다듬기가 왔는지 기록                                                                |
| BP-04 | P0   | 하루 1번(VC-05와 같은 호출) Croche가 변형 가중치 수정 제안 → 우리 앱이 합 1 유지·변화 ±0.1 한도 확인 후 적용 |

### 3.13 캐릭터 크기와 투명도 (LK)

목표: 사용자가 고양이의 **크기**와 **투명도**를 바꿀 수 있다. 화면이 좁거나 작업에 집중할 때 고양이가 방해되지 않게 하기 위해서다. 전부 우리 앱, Croche 관여 없음.

| `hover_fade` 마우스를 올리면 흐려지기 | 켬/끔               | 끔                 | —   |

| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------- |

**데모에 넣는 자리:** 투명도 슬라이더를 20%로 내리는 장면 → 이름이 `투명냥이 (원래 흰냥이)`로 바뀌고 "나 안 보여?" → 다시 100%로 올리면 "짠!". 크기·투명도 설정 기능과 캐릭터성을 한 번에 보여 준다.

**데모 모드:** 시연 화면(프로젝터) 크기에 맞춰 시작 크기를 정할 수 있게, 데모 모드 설정에 `scale` 시작값을 둔다 (RC-04).

**수용 기준:** 오른쪽 클릭 메뉴와 `Ctrl/Alt + 휠`로 크기 50~200%, 투명도 20~100%가 바뀌고, 앱을 껐다 켜도 유지된다. 200%로 키우면 좁은 발판에서 넓은 발판으로 옮겨 가고, 투명도 20%에서도 쓰다듬기가 된다. 말풍선 글자 크기는 바뀌지 않는다.

### 3.14 이동 리듬: 언제 움직이고 얼마나 머무를지 (MV)

목표: 고양이가 **언제 이동을 시작하고, 한자리에 얼마나 머무르고, 어디를 좋아하고 피할지**를 값으로 저장하고, 사용자의 행동(특히 드래그로 치우기)에 따라 바꾼다. 어디로 갈지는 §3.7·§3.8, 여기서는 **리듬과 장소 선호**를 다룬다.

#### 이동 프로필 (`motion`)

| 필드                | 뜻                                                                                             | 범위                                | 초기값                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------- |
| `rest_sec[상태]`  | 한자리에 머무는 시간. 사용자 상태(타이핑 중 / 쉬는 중 / 자리 비움 / 밤)별 최소~최대            | 10초 ~ 30분                         | 타이핑 중 3~8분, 쉬는 중 30초~2분, 자리 비움 5~15분(주로 잠), 밤 10~20분 |
| `move_prob[상태]` | 머무름이 끝났을 때 실제로 움직일 확률 (아니면 다시 머무름)                                     | 0.1 ~ 0.9                           | 타이핑 중 0.3, 쉬는 중 0.7                                                 |
| `roam_range`      | 한 번에 이동하는 거리                                                                          | 가까운 발판 / 같은 창 / 화면 어디든 | 같은 창                                                                    |
| `walk_speed`      | 걷는 속도                                                                                      | 느림·보통·빠름                    | 보통                                                                       |
| `zone_pref`       | **화면 구역 선호**: 모니터를 8×6 칸으로 나눈 칸별 점수                                  | −1 ~ +1                            | 0                                                                          |
| `app_zone_pref`   | **앱 안 구역 선호**: 앱 이름 × 창 안의 위치(위 왼쪽·위 가운데·위 오른쪽·아래쪽) 점수 | −1 ~ +1                            | 0                                                                          |
| `blocked_zones[]` | 사용자가 명시적으로 막은 곳                                                                    | 구역 + 만료일                       | 없음                                                                       |
| `follow_active`   | 활성 창 쪽으로 가려는 정도                                                                     | 0 ~ 1                               | 0.5                                                                        |

초기값은 VC-01과 같은 시드로 범위 안에서 약간 랜덤 (고양이마다 부지런한 정도가 다름).

#### 움직임 결정 순서 (우리 앱)

1. 이벤트 행동(§3.7)이 있으면 그게 먼저다 (말 걸러 가기 등).
2. 없으면 현재 사용자 상태의 `rest_sec` 범위에서 머무를 시간을 뽑는다.
3. 시간이 끝나면 `move_prob`로 움직일지 정한다.
4. 움직이면 `roam_range` 안의 발판 후보마다 **장소 점수** = 발판 선호(§3.8) + `zone_pref` + `app_zone_pref` + `follow_active` × (활성 창까지 가까움) 를 매겨 가중 랜덤으로 고른다. `blocked_zones`는 후보에서 뺀다.

#### 사용자 신호 → 변화

| 신호 (우리 앱이 감지)                                  | 변화                                                                | 고양이 반응                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------- | ---------------------------------------------- |
| **드래그로 치움**: 고양이를 잡아 200px 이상 옮김 | 원래 있던 칸·앱 구역 −0.3, 놓은 칸 +0.1                           | "어디 데려가?" (템플릿)                        |

| 메뉴 [여기 오지 마]                                    | 그 구역`blocked_zones` 30일                                       | "알았어"                                       |
| 메뉴 [가만히 있어]                                     | 30분 이동 정지 (이벤트 이동만 허용)                                 | 앉아서 꼬리만                                  |
| 대화 "좀 가만히 있어", "돌아다니지 마"                 | Croche가`motion_patch`로 바꿔 보냄 → 우리 앱이 범위 확인 후 적용 | "알겠어, 덜 돌아다닐게"                        |
| 쉬는 중에 고양이를 자주 쓰다듬음                       | 쉬는 중`move_prob` +0.05 (놀아 주는 사람에겐 활발하게)            | —                                             |

### 3.15 말 걸기와 대화 (TK)

목표: 고양이의 매력은 **무엇을, 언제, 어떻게 말 거느냐**에서 나온다. 대화 소재를 계속 만들어 내고, 사용자의 반응 패턴을 보고 소재·말 거는 방법·대화 길이를 바꾼다.

역할 경계(§1)를 그대로 따른다: **소재 후보를 모으고 고르는 것, 말 걸 시점, 반응 측정, 규칙에 따른 변화는 우리 앱.** 구체적인 문장, 대화 이어 가기, 새 소재 아이디어, 하루 단위 변화 제안은 Croche.

#### 3.15.1 대화 소재 은행 (`topic`)

소재를 **은행**에 쌓아 두고, 말 걸 때 거기서 고른다. 문장이 아니라 "무엇에 대해 말할지"를 저장한다.

| 필드              | 뜻                                               | 예                                                                      |
| ----------------- | ------------------------------------------------ | ----------------------------------------------------------------------- |
| `id`, `type`  | 종류 (아래 표)                                   | `data`                                                                |
| `text_hint`     | 무엇에 대해 말할지 한 줄 (문장 아님)             | "사용자가 오늘 평소보다 일찍 시작함"                                    |
| `conditions`    | 쓸 수 있는 조건                                  | `{time:"morning", user_state:"idle", needs:["activity.today_start"]}` |
| `weight_tags[]` | 반응 학습에 쓸 태그                              | `["공부", "칭찬"]`                                                    |
| `depth`         | 가벼움 / 깊음 (답을 오래 생각해야 하는지)        | 가벼움                                                                  |
| `needs_reply`   | 답이 필요한가                                    | false                                                                   |
| `cooldown`      | 다시 쓰기까지 최소 간격                          | 3일                                                                     |
| `stats`         | 사용 횟수, 답 받은 비율, 긍정 비율, 마지막 사용  | —                                                                      |
| `origin`        | 손으로 씀 / 데이터에서 자동 생성 / Croche가 제안 | —                                                                      |

**소재 종류와 만드는 방법**

| 종류                       | 예                                                                                                                                              | 만드는 쪽                                                                        | 만드는 때        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------- |
| `data` 내 데이터 소재    | 일정("시험 D-3"), 먹이("정규화 다 봤네"), 활동 변화("오늘 평소보다 일찍 시작했네", "오늘 집중 3시간"), 마일스톤("먹이 10개째", "함께한 지 7일") | **우리 앱** — 데이터 조건이 맞으면 자동 생성 (규칙 표로 정의)             | 데이터가 바뀔 때 |
| `time` 시간 소재         | 월요일 아침, 금요일 저녁, 점심시간, 자정 넘음, 계절·명절                                                                                       | 손으로 씀 + 달력 조건                                                            | 미리             |
| `self` 고양이 자신       | 배고픔, 애정도·레벨업, 오늘 숨바꼭질 결과, 이름 장난                                                                                           | 우리 앱 (고양이 상태에서)                                                        | 상태가 바뀔 때   |
| `question` 알아가기 질문 | "아침형이야?", "제일 좋아하는 간식은?", "요즘 뭐 공부해?"                                                                                       | 손으로 씀(30개) + Croche 제안                                                    | 미리 + 하루 단위 |
| `followup` 이어 가기     | 어제 "내일 면접"이라고 함 → "면접 어땠어?"                                                                                                     | **우리 앱이 대화 내역에서 날짜 있는 말을 뽑아 예약** (SC와 같은 날짜 추출) | 대화 직후        |
| `chitchat` 고양이 잡담   | "창밖에 새가 있었어(라고 상상함)", "꼬리가 간지러워"                                                                                            | 손으로 씀(30개) + Croche 제안                                                    | 미리 + 하루 단위 |
| `play` 놀이 제안         | 숨바꼭질, 이름 맞히기, 끝말잇기 한 판                                                                                                           | 손으로 씀                                                                        | 미리             |

초기 은행: 손으로 쓴 소재 약 80개 + 데이터 소재 규칙 15개 정도.

#### 3.15.2 말 거는 방법 (`opener`)

같은 소재도 **말 거는 방법**에 따라 느낌이 달라진다. 방법별로 반응을 따로 잰다.

| 방법                     | 모양                                                     | 답 부담       |
| ------------------------ | -------------------------------------------------------- | ------------- |
| `question` 질문형      | "요즘 뭐 공부해?"                                        | 큼            |
| `choice` 선택지형      | "오늘 기분 어때?" [최고] [그냥] [별로]                   | 작음 (버튼)   |
| `exclaim` 감탄·자랑형 | "오늘 3시간이나 집중했네!"                               | 없음          |
| `monologue` 혼잣말형   | "흐암… 졸리다냥" (말풍선 작게, 답 안 기다림)            | 없음          |
| `approach` 다가가기형  | 말없이 걸어와 앉아 바라봄 → 사용자가 클릭하면 그때 말함 | 사용자가 정함 |
| `beg` 조르기형         | "심심해. 놀아 줘" [놀아 주기] [나중에]                   | 작음          |

#### 3.15.3 말 걸 시점

| 요소                 | 규칙 (우리 앱)                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| 끼어들어도 되는 정도 | 입력 활발 = 낮음, 활발하다 멈춤 직후 = 높음, 쉬는 중 = 높음, 전체화면·조용 시간대·자리 비움 = 0           |
| 예산                 | 시간당`proactive_per_hour` 안에서 **기능 말(추천·일정·건강)이 먼저**, 잡담은 남은 예산의 최대 40% |
| 최소 간격            | 말 건 뒤 10분은 잡담 안 함. 사용자가 대화를 끝냈으면 20분                                                   |
| 특별 시점            | 그 날 첫 실행(인사), 며칠 만의 실행("보고 싶었어"), 마감 끝난 직후("수고했어"), 레벨업                      |

#### 3.15.4 소재·방법 고르기 (우리 앱)

1. 조건(`conditions`)과 쿨다운을 통과한 소재만 후보로.
2. **소재 점수** = 지금 상황과 맞는 정도 + 새로움(최근 쓴 것 −) + 반응 학습(그 `type`·태그·시간대의 긍정 비율) + **탐색 보너스**(10% 확률로 덜 써 본 소재·방법을 시험)
3. 1등 소재에 맞는 방법을 고른다: 방법 점수 = 방법별 반응 학습 + 소재와의 궁합(`depth`가 깊으면 질문형 대신 선택지형 등)
4. 말 요청(§1-2): `intent: chat_open` 또는 `followup`, `facts`에 `text_hint`와 필요한 데이터, `opener`, 말투(§3.9)를 넣어 Croche에 보냄 → Croche가 문장을 만든다.

탐색 보너스가 있어서 같은 고양이도 가끔 새로운 말을 걸고, 그 반응이 다음 선택에 쌓인다.

#### 3.15.7 사용자 패턴 → 변화 시나리오

**즉시·규칙 변화 (우리 앱, P0)**

| 패턴 (최근 대화 10건 기준)                    | 변화                                                                                                    |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 질문형에 무응답이 60% 이상                    | 질문형 비중 ↓, 선택지형·혼잣말형 ↑                                                                   |
| 답이 대부분 짧음 (단답형)                     | 선택지형 ↑, 턴 상한 6 → 3                                                                             |
| 답이 길고 빠름 (수다형)                       | 잡담 예산 40% → 60%, 깊은 소재·질문형 ↑, 턴 상한 6 → 10                                             |
| 특정 시간대에 무시가 3번                      | 그 시간대 잡담 금지 (기능 말은 유지)                                                                    |
| 특정 태그 소재에 긍정 비율 높음               | 그 태그 가중 ↑ (예: 공부 얘기 반응이 좋음 → 공부 소재 ↑)                                             |
| 특정 태그에 부정·무시                        | 그 태그 가중 ↓, 3번이면 2주 쉼                                                                         |
| 장난(이름·투명도)에 긍정                     | `prank_rate` ↑ (VC-N7)                                                                               |
| 칭찬 조르기를 자주 무시                       | 조르기 빈도 ↓, 대신 한 번 "쳇, 알았어"                                                                 |
| 최근 바쁨 (입력 강도 많음이 길게 + 마감 임박) | 잡담 예산 ↓, 응원형 짧은 말(감탄형)만                                                                  |
| 며칠 만에 돌아옴                              | 다음 첫 말은 "보고 싶었어" 특별 인사                                                                    |
| "말 걸지 마"                                  | 즉시 그 날 잡담 0,`proactive_per_hour` −1, 다음 날 아침 "어제는 조용히 있었어. 오늘은 괜찮아?" 한 번 |

**하루 단위 변화 (Croche 제안 → 우리 앱 검증, P1)**
하루 1번(VC-05와 같은 호출)에 아래를 보낸다:

- 하루 치 대화 기록 통계 (위 6번 표를 방법·종류·태그·시간대별로 묶은 숫자)
- 최근 대화 요약 3건 (로컬 내역에서)
- 사용자 성향 요약 (아래 3.15.8)

Croche가 돌려주는 것:

- `topic_weight_patch` (태그·종류별 가중치 변경 제안), `opener_weight_patch`
- **새 소재 아이디어** 최대 10개 (`text_hint`·`conditions`·`tags` 형식) → 우리 앱이 형식·금지 표현·중복 검사 후 은행에 추가 (`origin: croche`)
- 다음 날 해 볼 시도 1개 ("내일은 놀이 제안을 한 번 해 보기")

변경 한도: 하루에 가중치는 항목당 ±0.1, 새 소재는 10개까지, 은행 크기 상한 300개(넘으면 반응 나쁜 것부터 정리).

**사용자 성향 요약 (`user_profile_summary`, 하루 1번 갱신)**


#### 3.15.9 시나리오를 만드는 방법

1. **손으로 쓰는 핵심 시나리오 (P0, 해커톤 전)**: 사용자 유형 5가지(수다형·단답형·무시형·밤샘형·마감 압박형) × 상황 4가지(아침 인사·작업 중 빈틈·쉬는 중·밤) = 20칸. 칸마다 "어떤 소재를 어떤 방법으로, 반응하면 어떻게 이어 가고 무시하면 어떻게 하는지"를 한 줄씩. 이 표가 초기 가중치와 데모 대본의 근거다.
2. **Croche Studio 가상 사용자 (P0 검증, P1 확장)**: 위 5가지 유형을 가상 사용자로 설정해 며칠 치 대화를 자동으로 돌려 보고, 유형별로 규칙 변화(3.15.7)가 의도대로 일어나는지 확인한다. 예: 단답형 가상 사용자에게 사흘 뒤 선택지형 비중이 올라가는가. 발표에서 "이렇게 검증했다"의 근거가 된다.
3. **실사용 기록 (해커톤 이후)**: 실제 반응 통계로 초기 가중치를 다시 맞춘다.

#### 상황 계층과 눈치 (AD-05)

사용자 성향은 상황별로 따로 저장한다. 기준은 "켜져 있는 프로그램"이 아니라 **지금 앞에 있는 창(활성 창)**이다.

```
전체 성향
 └─ 상황 종류: 코딩 · 문서 · 웹서핑 · 영상 · 회의 · 게임
     └─ 앱: VS Code, Chrome …
```

```
지금 상황의 성향 = (그 상황 기록 수 × 그 상황 값 + k × 위층 값) ÷ (그 상황 기록 수 + k)
```

- 기록이 많은 상황은 자기 값을, 기록이 적은 상황은 위층 값을 따른다. 처음 쓰는 앱도 바로 동작한다.
- **k = 고양이의 `눈치` 성격 값.** 눈치 많은 고양이(k 큼)는 다른 상황에서의 기록도 크게 반영해 어디서든 조심하고, 눈치 없는 고양이(k 작음)는 지금 상황 기록만 본다. 초기값은 시드 랜덤(VC-01).
- 상황 종류는 앱 이름 + 창 제목 규칙으로 정한다(예: Chrome + 제목에 "YouTube" → 영상). 규칙에 없는 앱은 하루 1번 모아 Croche에 분류를 맡기고 결과를 저장해 다시 묻지 않는다.

### 4-1. 성능·최적화 (PF)

흰냥이는 **다른 작업과 동시에 하루 종일 켜져 있는 앱**이다. 고양이 때문에 PC가 느려지면 사용자는 바로 끈다. 그래서 성능은 기능과 같은 무게의 요구사항이고, 모든 기능은 아래 예산 안에서 동작해야 한다.

**설계에 주는 영향**

- 이동(WK)·판단(BH·MV·TK)·장난은 전부 로컬 규칙이라 AI 호출 비용이 없지만, **CPU 비용은 있다** → 모두 이벤트 기반 + 상태별 주기 조절로 만든다.
- 요소 정보 보강·화면 선 발판은 성능 위험이 가장 크다. 요소 정보 보강을 P1로, 화면 선 발판을 P0 후반으로 둔 것도 이 때문이고, 붙일 때는 PF-04·05 규칙을 지킨다.
- Electron은 기본 메모리가 크다(대략 100MB대). 언어 결정(§6-1) 때 메모리 예산을 함께 확인한다. 예산을 못 지키면 화면을 더 가벼운 방식(예: Tauri, 네이티브 창)으로 바꾸는 것을 검토한다.

**측정 계획:** AD-13 마감 전 테스트에 ① Electron 투명 창 + 걷기 애니메이션 CPU ② 보조 프로세스 메모리를 추가한다. 고양이 화면이 0.8%를 넘으면 앉아 있을 때 fps를 더 낮추거나(5fps) 정지 그림으로 바꾼다.

#### 사람별 담당 (AD-10의 경계 + 남은 구성요소 배정)
