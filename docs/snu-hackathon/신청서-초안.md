## 1. 신청서 항목 (제출용 문안)

### 3-1. 아이디어 / 서비스 (권장 500자 이내, 496자)

> 강의 자료·링크·과제 공지는 다운로드 폴더, 카톡, 브라우저 탭에 흩어지고, 정작 볼 때를 놓쳐 시험 며칠 전에야 "그 자료 안 봤다"를 깨닫습니다. 할 일 앱은 내가 정리해야 해서 며칠 쓰다 말고, 캘린더 알림은 금방 무시하게 됩니다. 흰냥이는 내 PC 화면 위에 사는 고양이입니다. 파일·링크·"10/31 시험" 같은 일정을 고양이에게 먹이처럼 던져 주기만 하면 고양이가 기억하고 마감을 따로 챙깁니다. 내가 일에 몰두할 때는 곁에서 조용히 지내다가, PC를 막 켰거나 하던 일을 끝낸 "뭐 하지?" 순간에 먼저 다가와 "과제 마감 내일이야. 정규화부터 하자냥" 하며 그 자료를 펼쳐 줍니다. 알림이 아니라 내가 기르는 고양이라서, 나를 기억하고 말투와 행동이 나에게 맞춰 자랍니다. AI는 먹인 자료를 읽어 정리하고, 앱이 고른 선택지 가운데 지금 할 말을 골라 고양이 말투로 전합니다. 최종 목표는 내 일상에 스며들어 화면 앞의 모든 시간을 곁에서 챙겨 주는 디지털 반려묘입니다.

### 3-2. 지속 가능성 / 사업화 방향 (권장 300자 이내, 208자)

> 대상은 PC로 공부하고 일하는 대학생·개발 학습자·직장인입니다. 먹인 자료와 함께 지낸 기록이 쌓일수록 고양이가 나를 더 잘 알게 되어 다른 앱으로 옮기기 어렵고, 고양이와의 관계 자체가 매일 켜 둘 이유가 됩니다. 기본 기능은 무료로 두고 고양이 종류·꾸미기·방 아이템과 주간 회고 리포트를 유료로 제공할 수 있습니다. 이후 모바일 연동과 친구 고양이 방문으로 넓힙니다.

### 3-3. Croche 활용 계획 및 필요한 AI 기능 (권장 500자 이내, 499자)

> 판단은 앱이, 선택과 말은 Croche가 맡습니다. 앱이 PC 활동으로 말 걸 시점을 정하고 행동+말 선택지 3~5개("말 안 걸기" 포함)를 제시하면, Croche가 배경정보를 보고 하나를 골라 고양이 말투로 말합니다. ① Context·Memory: 먹인 자료·일정·사용자 성향 중 지금 필요한 것만 넣고, 오래 남을 사실만 기억 ② Tool: 자료 열기·휴식 시작·일정 추가를 Tool로 등록해 대화 중 실행 ③ 비용·품질: 사용자가 기다리는 요청과 자료 정리 요청을 나눠 처리하고, Studio 가상 사용자로 "단답형 사용자에게 말 거는 방식이 바뀌는지" 검증 ④ Croche가 늦거나 실패해도 고양이는 정해진 문장으로 계속 움직입니다. ⑤ 새 말 선택지·소재 제안(앱이 검사 후 추가), 사용자가 답하면 이후 대화는 Croche가 이어 감. 2인이 앱과 AI 담당으로 나눠 주고받는 형식을 먼저 고정해 3일 안에 구현합니다. 제안: 앱이 먼저 말 거는 호출, 개인정보 칸 제한 기능.

글자 수는 공백 포함, Python `len()`으로 센 값(2026-10-09). 폼의 글자 수 세는 방식이 다를 수 있으니 붙여 넣은 뒤 폼에서 다시 확인한다. 핵심 이야기: "정리는 귀찮지만 키우는 건 즐겁다" — 자료 정리(A)와 놓침(B)을 먹이 주기와 먼저 꺼내 주기로 풀고, 알림이 아니라 기르는 고양이라 무시하지 않게 된다. B2B는 하지 않는다.

## 2. 데스크톱 앱이 가능한가

런타임 기능 기준으로 플랫폼 제약은 없어 보인다.

| 런타임 기능 | 플랫폼 의존? | 데스크톱에서 |
|---|---|---|
| 기억·맥락 관리 | 아니오 | 문제 없음 |
| 백엔드 불필요 | 아니오 (모바일도 Croche 클라우드 호출 구조일 것) | 동일 |
| 앱 기능 연결 | 앱 코드 쪽 | 파일 열기는 브라우저·모바일 샌드박스에서 막히지만 데스크톱은 가능 |

### 실제 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| SDK 언어 | 기반이 JS/TS(Node). Python(tkinter)에서 직접 호출 보장 없음 | 고양이 앱을 **Electron(JS/TS)**으로 만든다 |
| 도구 실행 위치 | 앱 기능 연결을 Croche 서버가 실행하는지, 앱이 콜백으로 실행하는지 미확인 | 아래 §3의 우회 설계로 위험을 낮추고, OT·메일로 확인 |
| 제출 규정 | 데스크톱 제출 불허 가능성 | 메일로만 해소 |

### 권장 구성
- Electron 한 앱: 투명·항상 위 창 + `shell.openPath` 파일 열기 + Croche SDK
- 관찰자(활성 창·입력 횟수)·SQLite: Node 라이브러리 또는 Python 별도 프로세스(로컬 HTTP로 연결). 3일 개발에는 언어 하나가 안전하나 Python 경험을 살리는 병행도 가능 — 팀에서 결정

## 3. 도구 실행 위치 우회 설계

전제: 모바일 앱에서 Croche가 동작하는 방식 그대로 쓴다. 모바일 앱도 로컬 파일을 직접 열 수 없고, "아이템 지급·예약" 같은 도구는 앱이 가진 기능이다. 그렇다면 Croche가 *무엇을 할지 결정*하고 앱이 *실제로 실행*하는 구조가 기본이라고 볼 수 있다. 흰냥이도 같은 구조로 만든다.

| 단계 | 하는 곳 | 내용 |
|---|---|---|
| 1 | 앱(로컬) | 먹이 등록 시 `food_id`·제목·과목·마감일만 Croche에 알리고, **파일 경로는 로컬 SQLite에만 보관** |
| 2 | Croche | 기억·맥락으로 추천 결정 → 액션 호출 `open_file(food_id=12)` (또는 구조화된 응답 `{action:"open_file", id:12}`) |
| 3 | 앱(로컬) | `food_id → 경로`를 로컬 DB에서 찾아 `shell.openPath`로 실행 |

효과:
- Croche가 도구를 서버에서 실행하는 방식이어도, 최악의 경우 "구조화된 응답을 앱이 해석해 실행"으로 우회된다.
- 남는 확인 사항: 앱 기능 연결이 콜백 방식인지, 구조화 응답만 가능한지는 OT에서 보면 된다. 어느 쪽이든 설계는 같다.
