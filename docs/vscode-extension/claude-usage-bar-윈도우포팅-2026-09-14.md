## 배경 — 왜 예약 작업이 필요했었나

원본 `claude-usage-bar` 확장은 **macOS 키체인에서만** 로그인 토큰을 읽는 구조라 Windows에서는 스스로 사용량을 가져올 수 없었음. 그래서 이전에(이 세션 이전) 우회책으로 **1분마다 도는 작업 스케줄러 예약 작업**(`ClaudeUsageBar`, `usage-fetch.mjs`를 vbs로 창 없이 실행)이 별도 데이터 파일을 쓰고, 확장은 그 파일만 읽는 구조로 땜질돼 있었음.

**친구 PC에 공유하려다 발견한 문제**: "확장자 수정해서 usage 계속 보이게 했는데 친구 컴퓨터에도 보낼 방법 있나요?" → vsix 하나로는 안 되는 게 확인됨. 확장 밖(예약 작업, vbs, fetch 스크립트, `settings.json`의 statusLine)에 핵심 로직이 있었고, 게다가:
- 스크립트·vbs·예약 작업에 `C:\Users\rexro` 경로가 하드코딩돼 있어 친구 PC 계정명이 다르면 그대로 안 돌아감
- 친구 PC에 Node.js가 설치돼 있어야 함
- 확장 ID·버전이 마켓 원본과 같아서, 마켓에 새 버전이 올라오면 자동 업데이트가 수정본을 덮어씀(이 PC도 같은 위험을 이미 안고 있었음)

## 결정 — 확장 안으로 로직을 합치기 (옵션 1)

두 가지 선택지(①확장 안에 윈도우용 토큰 읽기 함수를 넣어 통합 ②현재 구조 유지하고 스크립트 3개+설치 스크립트를 zip으로 묶어 배포) 중 사용자가 "자동 업데이트는 일단 끄고, 확장 안으로 합쳐보세요. 지금으로도 복구 가능하게"라고 결정 — **원상복구 가능성을 전제 조건으로 건 작업**.

**실제 수정 (모두 작업 사본 `~/claude-usage-bar-win/src`에서 진행, 원본은 그대로 둠)**:

| 위치 | 무엇을 바꿨나 | 왜 |
|---|---|---|
| `extension.js` 토큰 읽기 함수(신규) | macOS가 아니면 `~/.claude/.credentials.json`에서 직접 토큰을 읽음 | 원본은 macOS 아니면 빈 값만 반환하던 부분을 실제로 구현 |
| `extension.js` 에러 처리 | 401·403(인증 실패)일 때만 화면을 비우고, **429(요청 과다)일 때는 기존 표시값을 유지**한 채 대기 | **원본 자체의 버그 발견**: 429를 받을 때마다 이미 표시 중이던 사용량까지 지워버리고 있었음 |
| `extension.js` 시작 로그 | "v0.3.5-win" 문구 추가 | 원본 코드가 도는지 포팅판이 도는지 구분하려고 |
| `package.json` | 설명 문구 변경, 설치 메타데이터 제거 | 로컬 윈도우 빌드임을 표시, `vsce package`로 재패키징 가능하게 |

**복구 경로 확보**: 합치기 전 원본 상태의 vsix와 설치 폴더 통째 사본을 `backup/`에 미리 떠 둔 뒤 작업 시작 — `code --install-extension ...before-merge.vsix --force` 한 줄로 되돌릴 수 있게 준비.

## 검증 — "친구 PC처럼" 실제로 재현해서 실험

사용자 제안: "저희가 기존거 지우고 다운받아서 실험해보죠" → 실제 확장을 삭제하고 배포용 vsix로 재설치, 예약 작업도 끄고, 예약 작업이 써둔 데이터 파일도 치워서 **확장이 정말로 혼자 힘으로 사용량을 가져오는지** 재현.

- Monitor로 VS Code 확장 로그를 30분간 감시.
- 결과: 켜질 때 1회 + 이후 5분 간격 조회, **200 정상 응답**이 연속으로 찍히고 5시간 사용률이 조회마다 올라감(22%→26%→28%→…→42%, 안정화) → 429 없이 정상 동작 확인.
- 예약 작업을 켜 둔 채로는 확장과 호출이 겹쳐 429가 더 잦아진다는 것도 함께 확인 → 예약 작업은 끈 채로 유지하기로 함(완전 삭제는 안 하고 비활성화만, 필요시 `Enable-ScheduledTask`로 복구 가능).

## 결과

- 친구에게는 `claude-usage-bar-0.3.5-win.vsix` 파일 하나만 전달(채팅으로 `SendUserFile` 전송). 설치는 "Install from VSIX..."뿐, 별도 스크립트·Node·경로 설정 불필요 — 단, 친구 PC에 Claude Code 로그인은 돼 있어야 함.
- 트레이드오프: 갱신 주기가 1분→5분으로 늘고, VS Code가 켜져 있을 때만 갱신됨(예약 작업 방식보다 실시간성은 낮아짐).
- 토큰은 각자 PC의 로그인 파일에서만 읽고 외부로 전송되지 않음 — 단, 본인 PC의 `.credentials.json`이나 `usage-bar-data.json` 자체를 실수로 같이 보내면 안 된다는 점을 명시적으로 확인.

**검증한 것**: 문법 검사, 가짜 vscode 모듈로 돌리는 자체 점검 스크립트(로그인 상태/만료 토큰/가짜 토큰 3가지 케이스), 실제 재설치 후 20분+20분 두 차례 로그 관찰(총 9회 조회 전부 200 응답).
**검증 못 한 것**: 친구 PC에서의 실제 설치·동작(이 세션 안에서는 확인 불가, 파일 전달까지만 완료).
