## 4. 재현 방법

### 4.1 MediaPipe 처리속도

1. 1080p 30fps mp4를 준비한다(103 샘플 zip에서 꺼내거나 636 샘플). 경로에 한글이 있어도 `\`를 `/`로 바꿔 열린다.
2. 설정 5종: Holistic complexity 1(원본·640폭 축소), Holistic complexity 0, Pose(complexity 0/1)+Hands(`max_num_hands=2`) 분리. 모두 `static_image_mode=False`.
3. 프레임 150개마다 **디코딩 시간**, **추론 시간**, 손 검출 프레임 비율을 잰다.
4. 병렬은 `multiprocessing.Pool(4, 8)`에 **프로세스마다 다른 영상**을 주고 합계 fps를 본다.
5. 640폭 축소는 속도 이득이 없었다(병목은 추론이지 디코딩이 아님).

### 4.2 제공 키포인트(XML) 대 MediaPipe 비교

1. 636 샘플 27영상(`D:\dummy\New_Sample(…)\원천데이터`의 mp4와 `라벨링데이터\1.키포인트(xml)_TL`의 xml).
2. mp4는 Holistic complexity 1로 처리한다. 프레임을 640×360으로 줄여 넣고, 나온 정규화 좌표에 **(1920, 1080)을 곱해** XML과 같은 픽셀 좌표로 맞춘다. 4프로세스로 422초.
3. XML은 `outside="0"`인 요소만 읽고 프레임별 배열로 만든다(§ 데이터 사전 3.4).
4. 손 오차 = 21점 평균 `‖xml_j − mp_j‖ / ‖xml_0 − xml_9‖`(손목~중지 MCP 거리로 정규화). 유효 조건: XML 점 21개 중 15개 이상이 신뢰도 > 0.2, MediaPipe 검출됨, 스케일 > 20px.
5. 상체는 어깨너비(XML 점 2~5 거리) 대비 오차. 점 대응(BODY_25 → MediaPipe pose): 코 0→0, 오른어깨 2→12, 오른팔꿈치 3→14, 오른손목 4→16, 왼어깨 5→11, 왼팔꿈치 6→13, 왼손목 7→15(엉덩이 9·12 ↔ 24·23은 이제 안 씀).
6. 함께 잰 것: 같은 쪽 대 좌우 뒤바뀐 대응(뒤바꾸면 3.6~3.9로 폭증 → 같은 쪽), 프레임 정렬 오프셋 −3~+3(0에서 최소), 커버리지, 프레임 간 떨림.

### 4.3 636 스크립트 파싱 → `pairs.tsv`

1. `py7zr`로 `수어스크립트_TL.zip`을 임시 폴더에 푼다(xlsx 131개, 0.44GB).
2. 파일마다 `openpyxl`(read_only)로 행을 읽고 첫 열이 `Information`인 행에서 블록을 나눈다. 파일명은 그 행의 3번째 열, 한국어 문장은 다음 행의 3번째 열.
3. `sign_gestures_…`로 시작하는 행이 gloss 행이고 **다음 두 행이 start·end**다. 열 위치가 어긋나므로 **비어 있지 않은 값을 순서대로** 짝짓는다.
4. 시작 시간순으로 정렬해 gloss를 이어 붙인다. `Pool(6)`으로 109초.
5. 출력 열: `file, mode, cat, sub, korean, gloss, n_gloss, tracks`.
6. **알려진 손실:** gloss·start·end 개수가 다른 행은 버렸고 그 합이 39,295건이다(102개 파일). 통계는 이 누락을 반영하지 못했다.

### 4.5 Validation 형태소 JSON에서 수행자·문장·촬영정보 뽑기 (디스크에 풀지 않음)

각 JSON의 `metadata`는 파일 맨 앞에 있으므로 **앞 8KB만 메모리에 남기고 나머지는 버린다.** py7zr의 `WriterFactory`를 쓴다. 54.5GB를 LZMA2로 푸는 시간(약 22분)은 그대로 든다.

```python
import py7zr
from py7zr.io import Py7zIO, WriterFactory
KEEP = 8192; store = {}
class Sink(Py7zIO):
    def __init__(self, fn): self.fn = fn; self.buf = bytearray(); self.n = 0
    def write(self, s):
        if len(self.buf) < KEEP: self.buf += s[:KEEP - len(self.buf)]
        self.n += len(s); return len(s)
    def read(self, size=None): return b""
    def seek(self, offset, whence=0): return offset
    def flush(self): pass
    def size(self): return self.n
class Fac(WriterFactory):
    def create(self, filename):
        s = Sink(filename); store[filename] = s; return s
with py7zr.SevenZipFile(SRC) as a:
    a.extractall(factory=Fac())
```

정규식(**id는 숫자·실수 문자열·영문 숫자 조합이 섞여 있다**):

```python
IDV = r'"id"\s*:\s*("(?:[^"\\]|\\.)*"|-?\d+(?:\.\d+)?)'
rx_sig = re.compile(r'"signer"\s*:\s*\{[^}]*?' + IDV)
rx_trn = re.compile(r'"translator"\s*:\s*\{[^}]*?' + IDV)
rx_ko  = re.compile(r'"korean_text"\s*:\s*"((?:[^"\\]|\\.)*)"')
# 값 정규화: 따옴표를 벗기고 '116.0' -> '116'
```

- **추출 전에** 샘플 문자열로 `assert`를 돌려 정규식을 검증한다(이 검증이 기대값 오류를 몇 초 만에 잡았다).
- **추출 직후** 원본 prefix를 `pickle`로 저장한다(후처리가 실패해도 22분을 다시 쓰지 않도록).
- 파일명에서 문장 ID를 얻는 정규식: `re.sub(r"_\d+_(TW|KU|CROWD)\d+\.json$", "", 파일명)`.
- 특정 파일 몇 개만 볼 때는 `a.extract(targets=[…], factory=Fac())`(solid 아카이브라 앞 블록을 디코딩해야 해서 파일 2개에 54초).

### 4.6 신청서 양식 읽기

- **PDF**: `pypdf.PdfReader(경로).pages[i].extract_text()`. 표 안 글자 순서가 어긋난다(의미로 재조립해야 함).
- **HWP(5.x)**: OLE 컨테이너다. `olefile`로 `FileHeader`(37번째 바이트 bit0 = 압축 여부), `BodyText/Section0…`을 읽고 **압축이면 `zlib.decompress(data, -15)`**. 레코드는 4바이트 헤더(`tag = h & 0x3FF`, `size = h >> 20`, 0xFFF면 다음 4바이트가 크기)이고 **`tag == 67`이 문단 텍스트(UTF-16LE)**다. 제어문자는 걸러낸다. 일부 글자가 깨져 나온다(서명 필드 등). **hwp를 수정하는 도구는 없다** → 본문 텍스트를 만들어 사용자가 hwp에 붙여 넣는다.
