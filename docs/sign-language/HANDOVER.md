## 1. 프로젝트 한 장

- **무엇:** 웹캠으로 수어를 하면 한국어 자막을 내는 시스템. 학생 팀(1학년 3명)이 한양대 **SW·AI융합연구개발 일반과제**(6주 튜터링)에 신청하는 프로젝트이자, 그보다 큰 설계 목표를 가진 프로젝트다.
- **두 층의 목표가 있다. 섞지 말 것:**
  - **설계 목표(장기):** 연속 수어 → 한국어 문장 번역. 하위 프로젝트 A 키포인트 추출·데이터 준비 / B 단어 인식기 / C 연속 수어 → gloss 열(CTC) / D gloss 열 → 한국어. E 실시간 추론·데모와 F 평가·벤치마킹은 **목록에 추가할지 미결정.**
  - **신청서가 약속하는 것(6주):** 단어 인식 + 실시간 웹캠 데모. **문장(단어 열) 인식은 "향후 과제"**로 표기하고 선행 내용을 빠르게 마치면 착수. 한국어 문장 생성은 그 뒤.
- **세 번째 목표(사용자 2026-09-20): 환경 제약 조사와 극복 방법 도출.** 우리 데이터·모델·하드웨어·시간·전처리·학습 환경에서 생기는 한계를 조사하고 극복 방법을 찾는다. **신청서의 예상 산출물 중 하나**로 적는다. 지금까지 확인한 제약과 극복 후보·검증 상태는 [한계와-극복-방법.md](./한계와-극복-방법.md)이고 프로젝트 내내 갱신한다. 방법은 "제약 → 원인 → 극복 후보 → 시도 → 결과" 다섯 칸이며 **효과 없던 방법도 기각으로 남긴다.**
- **입력 표현:** MediaPipe 포즈·손 랜드마크 **53점**(상체 11 + 양손 42). 엉덩이는 사용자 결정으로 제외. 영상 픽셀이 아니라 좌표를 쓴다.
- **데이터:** AI-Hub **103 수어 영상**(단어 3,000·문장 2,000·지문자, 한국어 문장 없음)과 **636 재난 안전 정보 전달을 위한 수어영상 데이터**(재난·날씨 문장 약 14.9만, gloss·한국어 문장·시간정보 있음). 상세는 데이터 사전.
- **이 저장소의 역할:** 문서·태스크 메타 레포. **코드 레포는 아직 없다.** 코드는 한 줄도 프로젝트에 들어가 있지 않다(조사용 일회성 스크립트만 있음).
- **현재 단계:** 브레인스토밍(설계). 스펙·구현 계획·구현은 아직 시작하지 않았다. **연구과제 신청서는 2026-09-20 밤에 제출됐다(사용자 보고, 접수 확인은 못 함).** 무엇이 제출됐고 초안과 어떻게 다른지는 [제출본-2026-09-20.md](./제출본-2026-09-20.md). 제출본에는 **불일치 3건**(주제는 "번역"인데 본문은 "인식", "결과는 아래 표와 같다"가 가리키는 표가 없음, 산출물에서 벤치마크 표·실시간 데모 항목 누락)이 있다.

## 2. 사용자와 협업 방식

**사용자:** 팀 3명 중 한 명(1학년, 인공지능학과). 한국어로 대화한다. 수어·ML 전문가가 아니어서 "그게 뭔가요", "왜 필요한가요"를 자주 묻는다. **전문 용어는 풀어서, 근거와 함께** 설명해야 한다. 지시는 짧고 결정은 선택지로 답하는 편이며, 결정한 뒤에는 **"기록해 두세요"를 자주 요청**한다(결정·보류·미결을 구분해서 모두 기록).

**전역 규칙**(사용자 `~/.claude/CLAUDE.md`와 훅. 같은 PC의 Claude Code 세션은 자동으로 읽는다. 다른 환경이면 아래를 따른다):
- **답변과 진행 메모는 전부 한국어.** 코드·주석·커밋 메시지·경로·명령은 예외. 마지막 답변이 한국어가 아니면 훅이 막는다.
- **코드를 쓰기 전에 자연어 초안(무엇을·어디에·어떻게)을 보여 주고 승인받는다.** 승인 없이 코드로 넘어가지 않는다. 신청서 같은 **문서**는 사용자가 쓰라고 하면 쓰되, 방향이 갈리면 먼저 묻는다.
- **제안과 결정을 구분한다.** 사용자가 직접 답하지 않은 것은 "결정됨"으로 쓰지 않는다. 승인 없이 승인된 것처럼 보고하지 않는다.
- **간결하게.** Caveman·Ponytail 모드가 훅으로 켜져 있다(짧고 최소한으로). 다만 설명·근거·수정 사항 표는 이 프로젝트에서 요구되며 그 규칙이 우선한다.
- 제안·수정에는 **판단 근거와 이유**를 적는다. 분기·폴백이 있는 동작은 시간순 추적과 상황별 비교표로 설명(`explain-mechanism` 스킬).
- **보고 정확성:** 백그라운드 알림·Monitor의 수치를 그대로 보고하지 않고 **로그·결과 파일을 직접 열어 대조**한다. 재사용 스크립트에서 버그를 찾으면 **과거 결과까지 소급 점검하고 영향받은 결론을 무효로 표시**한다. 합성·더미 데이터로 검증된 것은 "코드가 돈다"까지다. 후보 비교는 검증 절차를 같게 맞춘 뒤에 한다.
- **파일을 수정한 작업의 마지막 답변에 수정 사항 표**(파일 링크|무엇을|왜, 새 파일·삭제 구분, 검증한 것과 못 한 것)를 붙인다. **남에게 보여줄 글(신청서 등)은 독자를 정하고, 넘길 때 첫 줄에 "Written for: …"를 쓴다**(파일 안이 아니라 메시지에).
- **AI 관여 표시 금지:** 커밋 메시지·문서에 `Co-Authored-By` 등 AI 표기를 넣지 않는다(사용자의 글처럼 쓴다).
- **git:** 리베이스·amend·`reset --hard`·강제 push 금지(훅으로도 막힘). 브랜치를 맞출 때는 merge. **이 레포(`task-management-repository`)는 커밋할 때마다 바로 push한다**(예외 규칙). 다른 레포·조직(`we-meet-trip`) 쓰기와 PR 생성은 매번 명시 승인. 커밋할 때는 `git add <경로>`로 **내 파일만** 스테이징한다(다른 세션의 미추적 파일이 많다).
- **동시 세션:** 다른 세션이 같은 레포·같은 PC를 쓴다. 남의 미추적 파일을 옮기거나 덮어쓰지 않는다. 도커·포트는 훅이 직렬화한다.

**이 프로젝트에서 사용자가 준 지침:**
- 심사는 "실제로 수행 가능한 계획인가"를 본다. 사전 진행 사실을 드러내면 유리하다(주제를 바꾸자는 뜻은 아님).
- 시각 자료가 있으면 승인이 잘 난다. 앱이면 Figma 화면을 낸다(이 과제는 앱이 아니라 구성도·목업·일정표로 대체 제안 중).
- 수치·클래스 수는 계획 단계라 **임시값**으로 두고 진행 시 확정. 역할 분담은 아직 적지 않는다.
- 결정한 것과 보류한 것과 안 한 것을 **모두** 기록한다.

## 3. 경위 (시간순, 2026-09-20 하루)

1. 사용자가 이전 대화(103·636 조사, 64프레임 윈도우, 경로 A/B, 55점)를 붙여 넣고 이어가기를 요청. `superpowers:brainstorming` 스킬을 다시 불러 **Architectural 경로**로 진행.
2. 데이터 조사: 103 라벨 zip, 636 스크립트(7-Zip 형식임을 발견, 200,986블록 파싱), 샘플 27개 구조.
3. **사용자 선택:** 목표 = 연속 수어 → 한국어 문장 번역. 하위 프로젝트 A~D로 분해, **A부터.**
4. 벤치마크: MediaPipe CPU 처리속도 실측 → 636 전체 재추출 약 34일이라 불가. **제공 XML(OpenPose)과 MediaPipe 좌표 비교(손 오차 중앙값 0.08~0.10)** → XML 변환 가능.
5. **사용자 선택:** 636은 XML 변환, 103은 MediaPipe. 이후 **엉덩이 제외 53점, 103은 처음엔 정면만**, 103에 한국어 문장이 없는 문제는 보류.
6. 636 수행자 조사: 파일명 토큰은 수행자가 아님(Validation JSON 20,091개의 `signer.id`로 확인, 51명). **"토큰 = 수행자" 가정 위의 결론을 무효 표시했다가 수행자 ID 기준으로 재확인.** 재추출이 정규식 오류·검증 기대값 오류로 두 번 실패한 뒤 성공.
7. 이 레포에 기록: `docs/sign-language/` 신설(MAP 소속이 아니라서), 색인 연결. **이 레포가 공개임을 발견**하고 글자 섞인 수행자 ID 4개가 커밋 이력에 공개돼 있음을 확인(§7 위험 1).
8. **연구과제 신청 시작:** 양식·공지 확인, 신청서 3쪽 빈 칸 5개와 주차별 계획 수정안 초안. 마감 확인 필요.
9. 사용자가 "향후 과제 = 문장 번역, 다른 데이터를 쓰면 어휘가 달라짐 → 필요하면 웹캠 직접 수집"이라는 생각을 밝힘 → 조건부 보류로 기록, 구매·데이터 제작 계획(신청서 초안 §9).
10. 이 인계 문서 작성.
