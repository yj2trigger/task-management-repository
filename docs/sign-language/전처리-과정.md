# 데이터 전처리 과정 (코드·이유·근거)

영상 한 클립이 모델 입력 `(64, F)` 배열이 되기까지의 단계별 기록. 코드 본체는 팀 레포 `yj2trigger/sign-language-recognition`의 `src/landmarks.py`, `src/preprocess.py`, `src/dataset.py`이며 아래는 핵심 부분 발췌다. 수치 근거는 `logs/sign-language/trials.md`의 T 번호.

원천 데이터(영상·좌표)는 AI-Hub 약관상 공유할 수 없어 D 드라이브에만 둔다. 이 문서에는 코드와 집계 수치만 적는다.

## 전체 흐름

```
영상(1920x1080, 30fps)
 → ① 라벨 구간 ±0.5초 잘라내기
 → ② 16:9 틀 맞추기 (세로·4:3 입력 대비)
 → ③ MediaPipe Holistic: 53점 (x, y) + 검출 마스크 [+ z]       ← landmarks.py, 클립별 npz 저장
 → ④ 어깨 기준 정규화
 → ⑤ 결측 채우기
 → ⑥ 손 상대 좌표 채널 추가
 → ⑦ 64프레임으로 리샘플                                          ← preprocess.build_features
 → ⑧ (학습만) 증강본 8벌 미리 만들기                               ← dataset.augmented_bank
 → 모델 입력 (64, 243)
```

## ① 라벨 구간 잘라내기

```python
t0 = max(0.0, start_s - margin_s)            # margin_s = 0.5
cap.set(cv2.CAP_PROP_POS_FRAMES, int(round(t0 * fps)))
n = int(round((end_s + margin_s - t0) * fps)) + 1
```

| 동작 | 이유 |
|---|---|
| 형태소 라벨의 시작·끝 시각 앞뒤로 0.5초씩 넓혀 읽는다 | 라벨 경계가 손 올리기·내리기를 잘라먹는 경우가 있어 여유를 둔다 |
| 클립마다 새 Holistic 객체를 만든다 | 앞 클립의 추적 상태가 다음 클립에 섞이지 않게 |

- 대상: 정면(F) 영상만. 300단어 × 수행자 18명(T-008, T-024).
- 손상 영상(`moov atom not found`)은 빈 결과로 제외, 1,500개 중 1개(C-14).

## ② 16:9 틀 맞추기 (2026-10-23 추가)

```python
def fit_16x9(bgr):
    h, w = bgr.shape[:2]
    if abs(w / h - TARGET_ASPECT) < 1e-3:
        return bgr                                   # 학습 데이터(16:9)는 그대로
    if w / h < TARGET_ASPECT:                        # 세로 영상: 좌우에 검은 여백
        ...cv2.copyMakeBorder(bgr, 0, 0, 좌, 우, BORDER_CONSTANT)
    ...                                              # 더 넓은 영상: 위아래에 여백
```

| 동작 | 이유 |
|---|---|
| 어떤 화면비든 16:9 캔버스 가운데에 넣고 남는 곳을 검게 채운 뒤 MediaPipe에 넣는다 | MediaPipe 좌표는 x를 너비, y를 높이로 나눈 값이라 화면비가 다르면 손 모양이 다르게 찌그러진다(C-16). 학습 데이터가 전부 16:9라서 입력을 16:9로 맞추면 재학습 없이 같은 좌표 단위가 된다 |
| 16:9 입력은 아무것도 하지 않는다 | 기존 추출 결과·실험이 그대로 유효 |

- 핸드폰 세로·가로 모두 지원하려는 요구에서 나왔다. 검증(세로 9:16·4:3로 잘라 흉내 → 원본과 비교)은 진행 중(T-035 예정).

## ③ 좌표 추출: 53점

```python
POSE_IDX = [0, 2, 5, 7, 8, 11, 12, 13, 14, 15, 16]   # 코, 눈2, 귀2, 어깨2, 팔꿈치2, 손목2
# 점 순서: 상체 11(0~10) + 왼손 21(11~31) + 오른손 21(32~52)
mask[k] = pose[idx].visibility >= 0.5                  # 상체: 가시성 0.5 이상만 유효
mask[start:start + 21] = True                          # 손: 검출되면 21점 모두 유효
```

| 동작 | 이유 |
|---|---|
| 몸 33점 중 상체 11점 + 양손 21점씩 = 53점 | 수어 정보는 상체·손에 있다. 하체·얼굴 메시는 뺀다 |
| 점마다 검출 여부(마스크)를 같이 저장 | 안 보인 점을 0 좌표와 구분해야 한다. 마스크 53개도 모델 입력에 넣는다 |
| MediaPipe 0.10.21 구형 Holistic 고정 | 신청서 사전 조사(속도·오차)를 같은 조건으로 재현, complexity 조절 가능(T-005) |

- 속도: 프레임당 complexity 1 = 43.2ms. 4프로세스 병렬로 분당 21~28클립(C-02, T-010).
- 출력: 클립별 `npz`(xy, mask, fps, word_id, signer, z, wh). 이미 만든 클립은 건너뛰고, `.tmp.npz`에 쓴 뒤 이름을 바꿔 중단돼도 깨진 파일이 남지 않는다.

## ④ 어깨 기준 정규화

```python
width  = |왼어깨 - 오른어깨|
center = (왼어깨 + 오른어깨) / 2      # 어깨가 안 보인 프레임은 가까운 유효 프레임 값
xy_norm = (xy - center) / width
```

| 동작 | 이유 |
|---|---|
| 어깨 중점을 원점, 어깨너비를 1로 | 카메라 거리·화면 속 위치·체격 차이를 지운다 |
| 클립(샘플) 단위로 계산 | 다른 샘플 통계를 쓰지 않아 학습·시험 간 정보 누수가 없다 |
| 어깨가 한 번도 안 보이면 클립 제외 | 기준이 없으면 좌표 단위를 정할 수 없다 |

- 대안 "코 기준 원점"은 시험 후 기각(T-028, 수행자 14의 손 높이 문제를 겨냥했으나 개선 없음).

## ⑤ 결측 채우기

```python
for p in 점 53개:
    결측 없음        → 그대로
    한 번도 안 보임   → 0
    결측 구간 길이 ≤ 5프레임이고 양쪽이 유효 → 선형 보간
    그 밖             → 가장 가까운 앞쪽 유효 값 유지
```

| 동작 | 이유 |
|---|---|
| 짧은 결측만 보간 | 손이 잠깐 놓친 경우는 움직임이 연속이라 보간이 맞다 |
| 긴 결측은 값 유지 | 긴 구간을 보간하면 실제로 없던 움직임을 만들어낸다 |
| 채운 프레임도 마스크는 "결측" 그대로 | 모델이 진짜 값과 채운 값을 구분할 수 있게 |

- 결측 없는 점은 건너뛰어 계산 시간을 줄였다(C-13).

## ⑥ 손 상대 좌표 채널

```python
size = |손목 - 가운뎃손가락 뿌리|
rel  = (손 21점 - 손목) / size          # 손 안 보이면 0
```

| 동작 | 이유 |
|---|---|
| 손목을 원점, 손 크기를 1로 한 손가락 좌표를 따로 추가 | 몸 기준 좌표에서는 손가락 모양 차이가 어깨너비 단위의 아주 작은 값이라 묻힌다 |

- **가장 중요한 채널.** 빼면 정확도 −0.14(T-017, E2).

## ⑦ 64프레임 리샘플

```python
src = np.linspace(0, n - 1, 64)        # 원래 길이 n 을 64칸으로 선형 보간
```

| 동작 | 이유 |
|---|---|
| 모든 클립을 64프레임으로 맞춤 | 모델 입력 길이 고정. 클립 길이 중앙값 77, p95 111프레임(T-008) |
| 리샘플 뒤 float32로 변환 | 보간 가중치가 float64라 그대로 두면 메모리 2배, torch와 형 불일치 |

- 부수 효과: 카메라 fps가 달라도 길이가 같아진다. 20fps 흉내 입력의 손실은 −0.004로 시드 간 편차보다 작았다(T-019, C-12).

## ⑧ 학습용 증강 (학습 데이터에만)

| 증강 | 값 | 이유 |
|---|---|---|
| 시간 구간 일부만 쓰기 | 80~100% | 수행자 간 속도 차(최대 약 40%, T-008) |
| 좌표 잡음 | 화면 폭의 0.5% | MediaPipe 흔들림 |
| 회전 | ±8° | 카메라 기울기 |
| 프레임 통째 결측 | 8% | 검출 실패 |

- 매 에폭 새로 증강하면 특징 계산이 병목이라 **증강본 8벌을 미리 만들어** 에폭마다 표본별로 한 벌을 고른다. 모든 모델·시드가 같은 증강본을 써서 비교도 공정해진다(C-13, T-009).
- fps 흉내 증강·손 위치 이동 증강은 효과 없어 기각(T-019, T-025).
