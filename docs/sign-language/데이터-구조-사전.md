### 2.2 이름 규칙 [확인]

- 단어: `NIA_SL_WORD<4자리>_REAL<2자리 수행자>_<시점>` (+ `_morpheme.json` 또는 `.mp4`). 예: `NIA_SL_WORD1501_REAL01_F.mp4`
- 문장: `NIA_SL_SEN<4자리>_REAL<수행자>_<시점>`
- 지숫자·지문자: `NIA_SL_FS<4자리>_CROWD<2자리>_F`
- 합성: `NIA_SL_SEN<4자리>_SYN<2자리>_<시점>`
- 시점: `F` 정면, `D` 아래에서 올려다봄, `U` 위에서 내려다봄, `L`·`R` 측면(비스듬함). **뜻은 정면·아래·위·옆 프레임을 한 장씩 본 추정**이며 문서로 확인한 것이 아니다. L과 R이 수행자 기준인지 카메라 기준인지는 모른다.
- 참고: 단어 Training 라벨의 시점별 파일 수는 47,994인데 zip 파일 총수는 240,000이라 5×47,994=239,970과 30개 차이가 난다. 원인 미확인.

### 2.3 형태소 JSON 스키마 [확인]

```
{ "metaData": { "url", "name", "duration"(초), "exportedOn" },
  "data": [ { "start"(초), "end"(초),
              "attributes": [ { "name": "<gloss>", ("attribute": ["<문법 표지>", ...]) } ] } ] }
```

- 한국어 문장 필드가 **없다.** 한국어 문자열은 `attributes[].name`(gloss)과 `attributes[].attribute[]`(문법 표지, 예: "1형태소 의문사 없는 의문형")뿐이다. 5개 zip에서 무작위 300개씩 재귀로 확인했다(표본이라 1% 미만 필드는 놓칠 수 있음).
- 단어 클립은 `data`가 항목 1개, 정면 47,983개는 1개이고 11개는 0개다.
- 예: WORD0001 = "고민", 1.743~3.103초, 영상 4.867초.
- 단어 구간 길이(정면, 47,983개): 중앙값 1.57초(47프레임), p95 2.7초(81프레임). 영상 길이 중앙값 4.13초, 시작 오프셋 중앙값 1.5초.
- 고유 gloss 2,963개(WORD ID 3,000개 중). 232개 gloss가 여러 ID에 걸치고, 264개 ID는 수행자마다 gloss 표기가 다르다.
- 문장 라벨(Training 표본 400개): 문장당 gloss 수 중앙값 3, 최대 7.

### 2.4 키포인트 JSON(프레임당 1개) [확인: syn zip 표본, 103 샘플 zip]

### 3.4 키포인트 XML 스키마 [확인]

CVAT 내보내기. 프레임마다 `track` 4개(라벨 `pose_keypoints_2d` 25점, `face_keypoints_2d` 70점, `hand_left_keypoints_2d` 21점, `hand_right_keypoints_2d` 21점). 각 `track`은 `points="x,y,conf;x,y,conf;…"`를 가진 자식 요소 2개(`frame=f, outside=0`과 `frame=f+1, outside=1`)를 가진다. **`outside=0`인 것만 읽는다.** 좌표는 1920×1080 픽셀 기준이다.

### 3.5 수행자와 토큰 [확인, Validation JSON 20,091개 = 전체의 10%]

- `signer.id` 고유 **51명**(숫자형 48, 영문·숫자 조합 3). 파일 수 편중이 크다(중앙값 171, 최대 2,954, 한 명이 14.7%, 상위 5명이 43.6%). 51명은 전체 수행자 수의 하한이다.
- **토큰 ≠ 수행자.** TW 38토큰 중 37개, KU 12토큰 중 11개는 수행자 1명이지만 CROWD 27토큰은 8개만 1명(평균 2.26명). 토큰 2개 이상을 쓰는 수행자가 19명이다.
- CROWD 토큰의 수행자 11명과 TW·KU 토큰의 수행자 40명은 **겹치지 않는다.**
- `filmed_in_studio`: TW·KU 전부 true, CROWD 전부 false(비스튜디오).
- 문장 ID 14,901개 중 99.97%(14,897개)가 수행자 1명이 수어했다.
- Validation은 수행자를 Training과 공유하고(토큰 77종 전부 겹침) 문장은 거의 분리돼 있다(문장 ID 14,901개 중 나머지 180,897개와 겹치는 것 69개).

### 3.6 수어스크립트 xlsx 스키마 [확인]

문장 블록이 세로로 반복된다. 각 블록:
```
'Information' | 'File name : ' | <파일명.json>
'Korean sentence : ' | <한국어 문장>
'Second : ' | 1 | 2 | 3 | …
<비수지 이름 예: 'Ci'> | 'descriptor : ' | …   (start(s)/end(s) 행이 이어짐)
'sign_gestures_<b|s|w…>' | … | <gloss들 …>        → 다음 두 행이 start(s), end(s)
```
- 블록은 첫 열이 `Information`인 행에서 시작한다. gloss 행의 열 위치가 start·end 행과 어긋날 수 있어서, **비어 있지 않은 값을 순서대로 짝짓는다.** 개수가 안 맞으면 그 행을 버리는 구현이었고, 그 결과 **39,295건(102개 파일)이 버려졌다**(WEATHER-1_1 한 파일이 17,365건). 누락 토큰 비율은 미측정이다.
- 수행자 정보는 xlsx에 **없다.**
