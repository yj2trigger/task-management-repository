## 1. 자료가 다룬 범위

| 항목 | 내용 |
|---|---|

| 처음 목표 | 웹캠 수어 → 단어 분류(30~50 클래스), 아키텍처 비교 벤치마킹, 실시간 데모 |
| 목표 변경 | 팀이 "문장 번역"을 원한다고 밝힘 → 웹캠 수어 영상 → 한국어 문장 자막, 범위는 "자유로운 일반 대화 문장" |
| 자료의 결론 | 자유 대화 번역은 이 데이터·인원·일정으로 사실상 불가능. **닫힌 어휘 기반 문장 번역**으로 조정하고, **2단계 구조**(영상 → gloss 시퀀스[CTC] → 한국어 문장)로 간다. 636을 주 데이터로 승격. 평가는 macro-F1이 아니라 WER(gloss)·BLEU(문장) |
| 자료가 열어 둔 질문 | "103 real_sen_morpheme에 한국어 원문 필드가 있는가" — 계획 전체의 분기점으로 지목 (→ §3에서 닫힘) |
| 조사한 데이터셋 | 103 수어 영상(2020, 53.6만 영상, 길찾기·교통·주소), 636 재난 안전 정보 전달 수어영상(2021 구축, 2022-07 갱신, 재난안전문자·날씨정보) |

## 3. 103 한국어 원문 확인 (2026-09-20)

103 라벨 zip 5종을 각각 무작위 300개씩 열어 JSON 키를 재귀로 훑었다.

| zip | JSON 수 | 최상위 키 | 한국어 문자열 |
|---|---|---|---|
| `01_crowd_morpheme` | 17,000 | `metaData`, `data` | gloss 이름(`attributes[].name`)뿐 |
| `01_real_sen_morpheme` | 160,000 (SEN0001~2000 × REAL01~16 × 5시점) | `metaData`, `data` | gloss 이름과 문법 표지 `attributes[].attribute[]`(예: "1형태소 의문사 없는 의문형")뿐. 문장 아님 |
| `01_real_word_morpheme` | 240,000 | `metaData`, `data` | gloss 이름뿐 |
| `01_syn_sen_keypoint` | 309,646 | 키포인트(2D·3D pose/face/hand, 카메라 파라미터) + 일부 `SEN/morpheme` | 표본 300개 중 형태소 JSON은 3개뿐이라 근거가 약함. 그 3개에는 문장 없음 |
| Validation 추가분 `01_real_sen_morpheme` | 20,000 | `metaData`, `data` | gloss 이름과 문법 표지뿐 |

결론: **103 라벨 JSON에는 한국어 문장이 없다.** gloss 시퀀스와 시간정보만 있다. 한국어 원문이 있는 곳은 636뿐이다(수어스크립트 xlsx의 `Korean sentence :`, 형태소 JSON의 `korean_text`, 고유 문장 약 14.9만).

한계: 표본이 300개이므로 1% 미만 파일에만 있는 필드는 놓칠 수 있다. 103의 원천 영상 zip, real_word 키포인트 zip, 데이터 설명서는 받지 않아 열어 보지 않았다.

Validation 추가분 폴더 이름의 `_231204_add`는 2023-12-04 추가 라벨링을 뜻하는 것으로 보인다(폴더명 기준 추정). 이 추가분이 **수행자 REAL17·REAL18을 문장 SEN0001~2000에 붙인 것**이라면 103 문장에는 학습과 수행자가 겹치지 않는 검증 집합이 이미 있다는 뜻이다. 수행자 집합 확인은 아직 하지 않았다.

## 4. 자료가 남긴 결정 항목과 현재 상태

"자료의 제안"은 검증되지 않은 권고다. 해당 하위 프로젝트(B 단어 인식기, C 연속 수어→gloss, D gloss→한국어, E 실시간, F 평가)의 설계 때 각각 결정한다.

| 영역 | 자료의 제안 | 상태 |
|---|---|---|
| 환경 | `pyproject.toml` + uv lock, Colab용 `requirements.txt`는 export. PyTorch 권장(ST-GCN 등 구현 다수, 학습 루프 통제 쉬움), ONNX export를 CI에 | 미결정 |
| 아키텍처 후보 | BiLSTM(베이스라인), TCN, Transformer Encoder, ST-GCN(스코프 컷 1순위) | 미결정. 목표가 문장 번역으로 바뀌어 출력층은 CTC로 |
| 입력 특징 | 정규화 좌표 + 프레임 간 차분(속도) + 관절 각도 + 유효 마스크. 얼굴 468점은 제외 | 마스크는 A 설계에 반영. 나머지 미결정 |
| 정규화 | 목(양 어깨 중점) 원점 + 어깨너비 스케일, 손 국소 정규화(손목 원점·중지 MCP 스케일)를 별도 스트림으로 | B·C 로더에서 결정 |
| 결측 처리 | 3프레임 이하 선형 보간, 그 이상 forward fill, 손 결측 30% 초과 클립 폐기, 마스크 채널 항상 부착 | 마스크만 반영. 30%는 자료의 제안값 |
| 증강 | 시간 리샘플 0.8~1.25배, 랜덤 크롭, 프레임 드롭 5~10%, 좌표 지터 σ=0.01, 2D 회전·스케일, 관절 드롭아웃. 좌우 반전은 주의(주 사용 손이 바뀜) | 미결정 |
| 데이터 분할 | 수행자 독립 분할 원칙, 분할 파일을 커밋. 103은 예로 14/3/3명 | 103에는 적용 가능. **636은 파일명 토큰이 수행자가 아니라서 재설계 필요**(설계 기록 §6.2) |
| 가변 길이 | 고립 단어는 고정 길이 리샘플, 연속은 CTC, 추론은 슬라이딩 윈도우 | 문장 목표라 CTC 쪽 |
| 클래스 불균형 | 정도별: 1:3 이하 방치, ~1:10 가중 손실, ~1:100 샘플러 + Focal, 20개 미만 클래스 제외 | 문장 목표에서는 gloss 분포(롱테일)에 맞춰 재검토 |
| 재현성·균등 노력 | 시드 고정, YAML 설정, 커밋 해시 로그, 모델별 동일 탐색 예산(예: 20회)·동일 탐색 공간·동일 조기 종료·동일 입력·동일 시드 집합 | 미결정 |

| 평가 지표 | gloss 단계 WER, 문장 단계 BLEU 또는 완전일치. macro-F1≥0.80 탈락 기준은 폐기하고 WER로 교체(예: WER ≤ 30%) | 미결정. WER 30%는 자료의 예시 |
| 통계 신뢰성 | 시드 3개 평균±표준편차 + 부트스트랩 95% CI + 최종 두 모델만 McNemar | 미결정 |

| 확정 규칙 | 확률 EMA + 임계값 + k회 연속 + 쿨다운, 연속 검증 영상으로 격자 탐색, 이벤트 F1 | E 설계 때 |

| 스코프 컷 순서 | ST-GCN → 외부 영상 평가 → 연속 후처리 → 클래스 수 축소 → 탐색 예산 → 시드 → 파인튜닝. 자르지 않는 것: 수행자 독립 분할, FPS/지연 분리 측정, idle 대책, 연속 검증 영상 | 미결정 |

## 5. 현재 분해에 빠져 있는 것

현재 하위 프로젝트 A~D는 모델 파이프라인만 다룬다. 자료가 다룬 아래 두 영역은 목록에 없다.

- **E. 실시간 추론·데모**: 웹캠 캡처, 슬라이딩 윈도우 또는 스트리밍 디코딩, 확정 규칙, UI, 스레드 분리
- **F. 평가·벤치마킹**: 지표 정의, 재현성 정책, FPS·지연 측정, 탈락 기준, 통계 검정

E·F를 하위 프로젝트로 추가할지는 미결정이다.
