## 이 세션에서 확인된 것 — 이미 EDK(의약품) 도메인이었음

세션 시작 시점에 이미 `medicines.json`, `symptom.py`, `drug_controller.py` 등 **의약품 키오스크**로 전환이 끝나 있었음(별도 세션에서 이뤄진 전환으로 보이며 이 세션엔 없음). 이 세션의 전반부는 그 위에서 진행된 유지보수:

- **가격 정규화**: "상품 가격에서 100원, 500원단위를 없애고 최소 1000원단위로 진행하세요" → `medicines.json`(5,500/3,500/4,500원 → 6,000/4,000/5,000원)과 `options.json`(옵션 추가금 200~500원대 다수)을 1,000원 단위로 반올림. 1차로 일부 옵션을 0원으로 낮췄다가 "0원은 말이 안되니까 최소 1000원으로 하세요"라는 피드백을 받아 전부 최소 1,000원으로 재수정 — **정책을 한 번에 못 맞히고 사용자 피드백으로 두 번째에 확정**된 사례.
- **보안 질의응답**: "exe파일에는 암호화 키를 넣으면 보안이 안좋겠죠?" → PyInstaller exe가 `pyinstxtractor`/`uncompyle6`로 디컴파일 가능함을 근거로 위험성 확인. 이어서 "결국 비번 검증 로직을 보면 암호를 알 수 있지 않나요?"라는 재질문에 **scrypt는 단방향 함수라 알고리즘이 노출돼도 역산 불가(Kerckhoffs 원칙)**임을 설명하되, **`main.py`에 기본 관리자 비번 `"1234"`가 하드코딩된 실제 취약점**을 짚어냄 — "알고리즘 노출은 무해하나 기본값 노출은 실제 위협"이라는 구분이 핵심.
- **문서 동기화**: 이 작업 내용을 GitHub `task-management-repository`의 `done.md`와 `portfolio/ic-pbl/README.md`에 직접 반영(MCP로 push) — 로컬 코드 저장소와 개인 문서 저장소가 이때부터 이미 연동되어 있었음.
- **교수 피드백 포인트 정리**: 사용자가 "교수님께 어떤 부분을 피드백받으면 좋을까요?"라고 묻자, 재고 설계(수량 없이 ON/OFF만)·**도메인 전환의 타당성**(Coffee/Gummy→EDK 전환이 과제 범위를 벗어나는지)·TTS 인터넷 의존성·증상→의약품 매핑의 약학적 근거·기본 비번 취약점 5가지를 제시, 그중 "도메인 전환 타당성"을 가장 중요한 것으로 꼽음. **이 지적이 바로 다음 대화에서 실제로 터짐.**

## 두 번째 도메인 전환 — EDK(의약품) → 아이스크림 (2026-05-26T06:17Z)

사용자: "의약품은 재고를 어떻게 해야할지 애매해서 아이스크림으로 변경하기로 했어요." — 위에서 스스로 짚었던 "재고 설계가 애매하다"는 우려가 실제 전환 사유가 됨.

**새 상품 정의**: 아이스크림 2종
1. **스틱 아이스크림** — 실루엣(직사각형/원형/별/하트) × 코팅색 5종 × 토핑 4종
2. **스쿱 아이스크림** — 용기(컵/콘) × 스쿱 수(1~3개) × 스쿱별 맛(각 슬롯마다 5종 중 선택)

**구현 방식 결정 — 이미지 파일 대신 QPainter 실시간 렌더링**: 사용자가 "이미지로 결과물을 제시할 수 있기를 원한다"고 요구 → Claude가 AskUserQuestion으로 확인 질문을 던진 뒤 **외부 이미지 에셋을 두지 않고 PyQt6 `QPainter`로 도형을 코드로 직접 그리는 방식**을 제안·채택. 이유: 추가 의존성 없음, 옵션 변경 시 `update()` 한 번으로 즉시 재렌더링.

**스쿱 UI 세부 결정**: 스쿱 3개 슬롯을 항상 보여주고 "없음"을 옵션에 넣는 방식으로 초안이 나왔으나, 사용자가 "'없음'방식 대신 '그만 쌓기' 등 더 직관적인 메시지로 변경하세요"라고 요구 → 슬롯 2·3에 "그만 쌓기" 선택지를 넣어, 그걸 고르면 다음 슬롯이 아예 숨겨지는 방식으로 확정. **UI 문구 하나도 사용자 검수를 거쳐 정해진 사례.**

**구현 실행 (07:01~07:17Z)**: 승인 후 8단계로 일괄 진행 — 데이터 파일(products/ingredients/options.json) 교체 → 모델(`medicine.py`→`ice_cream.py`, `symptom.py` 제거) → `DataManager` 갱신 → 컨트롤러 수정 → `stick_preview.py`/`scoop_preview.py` 신규 위젯 작성 → GUI 화면(idle/main_menu/customize/admin_menu) 재작성 → `main_window.py` 네비게이션 정리 → 실행 테스트. **`admin_auth.py`가 옛 `go_to_symptom_select` 메서드를 호출하던 걸 놓칠 뻔했으나 실행 전 점검에서 발견해 수정**.

**세션 종료 시점**: GUI가 에러 없이 실행되는 것까지 확인. "다른 프로젝트 진행할 예정"이라는 사용자 지시에 따라 미완료 항목(레거시 파일 삭제, 테스트 코드 업데이트)을 이 프로젝트 자체의 Claude 메모리(`~/.claude/projects/.../pmg-ic-pbl/memory/`)에 저장하고 세션 종료 — **재개 시 문서가 아니라 세션별 memory 파일에서 상태를 복구하는 방식**으로, CLI판(`CURRENT_STATE.md` 파일 기반)과는 다른 상태 관리 방식이 쓰였음.
