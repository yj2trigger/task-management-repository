## 2026-09-10T09:47Z ~ 10:56Z — 디스크 공간 부족으로 에뮬레이터 부팅 실패

**시작**: 에뮬레이터 화면 캡처만 첨부된 "?" 메시지 → 맥락 재요청 후 스크린샷 확인, 에러 메시지에서 즉시 원인 특정: `Not enough space to create userdata partition. Available: 7884.68 MB`.

**타 AI 가설 반박 요청**: "다른 ai는 애뮬레이터가 c드라이브 용량을 잘못 측정했을 가능성을 제시했어요" → **PowerShell 드라이브 조회, `Get-Volume` API, 에뮬레이터 자체 표시값 세 가지 독립 소스를 대조**해 전부 7.7GB 근방으로 일치함을 근거로 "측정 오류 가능성 낮음, 진짜 공간 부족" 반박. 다른 AI가 그런 가설을 낸 배경(과거 에뮬레이터의 SSD 볼륨 계산 버그 사례, OneDrive 클라우드 전용 파일로 인한 표시 왜곡 — 단, 이건 반대 방향으로 왜곡됨)까지 짚어줌.

**정리 실행**: 승인 받아 SDK `system-images` 스캔 → 안 쓰는 `android-37.0`(2.74GB, sdkmanager로 삭제) + 설치 실패로 남은 빈 폴더 2개 정리, 여유공간 7.7GB→10.43GB로 회복. 그러나 로그 분석 결과 실제 필요량이 `disk.dataPartition.size=10G` + 에뮬레이터 자체 여유분 2G = **12GB**임을 idea.log에서 정확히 찾아내, "10GB 넘겼다고 안심하면 안 됨"을 지적.

**해결책 갈림길**: 디스크를 계속 비우는 대신 **AVD 파티션 크기 자체를 6GB로 축소**하는 방향을 권장(연습용 앱에 6GB면 충분, 필요량이 8GB로 줄어 현재 여유로 바로 충족). 사용자 승인 하에 `config.ini`의 `disk.dataPartition.size=10G`→`6G` 직접 수정, Wipe Data는 불필요함(아직 userdata 이미지가 한 번도 안 만들어진 상태)을 확인 후 수정.

**마지막 질문 — 코드는 문제없고 실행 설정이 문제였던 사례**: "제가 짠 코드를 애뮬레이터로 작동시켜서 보는 방법을 모르겠어요" → 코드가 아니라 상단 **실행 구성이 `Tests in 'Hello.app'`로 되어 있어 ▶를 눌러도 테스트만 실행**되고 있었음을 스크린샷에서 특정. `app` 구성으로 바꾸는 절차와, 참고로 `@Preview`를 이용하면 에뮬레이터 없이도 빠르게 화면 확인 가능하다는 팁 추가.
