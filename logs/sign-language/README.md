# 수어 번역 시스템 개발 기록

SW·AI융합연구개발 일반과제 "랜드마크 기반 딥러닝 모델을 활용한 실시간 수어 번역 시스템 개발"(2026.10~2026.11)의 진행 기록. 보고서(텍스트형·PPT형)의 원자료다.

## 어디에 무엇을 두나

| 위치 | 내용 |
|---|---|
| 이 폴더 `logs/sign-language/` | 일지, 시행착오, 제약 표, 그림 목록, 주별 보고 초안 |
| 팀 코드 레포 `sign-language-recognition` (GitHub, private) | 코드, 설정, 분할 파일, 실험 결과(`runs/`), 그림 생성 스크립트(`figures/`) |
| 로컬 D 드라이브 `D:\sign-language-data` | AI-Hub 원본 영상, 추출한 좌표 배열 등 용량이 큰 데이터 (C 드라이브 여유가 적어 모두 D에 둔다) |

## 파일 구성

| 파일 | 용도 |
|---|---|
| `daily/YYYY-MM-DD.md` | 날짜별 일지. 팀 전원이 한 파일에 작성자 이름을 붙여 **덧붙이기만** 한다(이미 쓴 내용은 고치지 않음) |
| `trials.md` | 시행착오 누적. 기각한 것도 바로 적는다 |
| `constraints.md` | 제약 → 원인 → 극복 후보 → 시도 → 결과 표 (필수 산출물) |
| `figures-index.md` | 보고서에 쓸 그림의 번호·캡션·생성 방법 |
| `weekly/W1.md` ~ `W6.md` | 주별 활동보고서 초안. 금요일에 daily와 trials를 모아 작성 |

## 기록 규칙

1. 수치는 알림이나 화면 출력이 아니라 **로그 파일을 열어 대조한 값**만 적는다.
2. 샘플·합성 데이터로 얻은 결과는 `[샘플 검증]` 태그를 붙인다. 코드가 도는지까지만 확인한 것이고, 결론은 실데이터로 다시 확인한다.
3. 여러 번 재사용하는 스크립트에서 버그를 찾으면 고치는 데서 끝내지 말고, 그 스크립트로 낸 과거 결과를 점검해 영향받은 항목의 `무효 표시`를 채운다.
4. 후보 모델을 비교할 때는 분할 파일·시드·탐색 예산을 전부 같게 맞춘 뒤 비교한다.
5. 보고서 그림은 AI-Hub 원본 프레임 대신 **좌표만 그린 스켈레톤 이미지**를 쓴다(이용 조건: 팀 안에서만 사용). 웹캠 데모 화면은 본인 동의를 받은 팀원 화면만 쓴다.
6. 코드는 문서에 복사해 붙이지 않고 **커밋 해시와 경로**로 참조한다. 보고서에 넣을 핵심 조각만 마지막에 발췌한다.

## ID 규칙

- 시행착오: `T-001`, `T-002` …
- 제약: `C-01`, `C-02` …
- 그림: `W{주차}-{번호}` (예: `W1-02`)

## 데이터 관리 방침

교수님 지침("데이터 관리는 GitHub에서")에 따라 다음을 팀 레포에서 관리한다.

- 단어 클래스 목록, 수행자 분할 파일, 데이터 목록(매니페스트)과 파일 해시
- 추출·변환 스크립트, 전처리 설정
- 실험 결과 JSON

원본 영상과 대용량 좌표 배열은 GitHub의 파일 크기 한도(파일당 100MB)와 AI-Hub 이용 조건(팀 안에서만 사용) 때문에 올리지 않고 D 드라이브에 둔다. 이 방침은 교수님 의도와 맞는지 확인이 필요하다.
