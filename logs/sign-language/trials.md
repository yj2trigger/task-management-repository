### T-002 | 2026-10-18 | 사전 | [유재준]
- 가설: 신청서가 근거로 든 "수행자 51명(검증 데이터 기준)"으로 단어 데이터에서 수행자 독립 분할을 할 수 있다.
- 시도: 받은 004 Validation 단어 라벨 zip의 파일 이름에서 수행자·시점·단어 번호를 집계(30,000항목).
- 결과: Validation 단어 데이터의 수행자는 **2명(REAL17, REAL18)**. 시점은 D·F·L·R·U 5개가 각 5,998개, 단어 번호 3,000종(0001~3000). Training 단어 라벨의 항목 수 240,000 = 16명 × 3,000단어 × 5시점으로 계산이 맞아 Training 수행자는 REAL01~16(16명)으로 보인다. 단어 데이터 전체 수행자는 약 18명이다. [실데이터]
- 판정: 가설 기각. "51명"이 어느 데이터를 가리키는지(예: 문장 데이터나 114 재난 데이터)는 확인하지 못했다.
- 다음: 수행자 독립 분할을 약 18명 안에서 설계한다(예: 학습 12 / 검증 3 / 시험 3명 단위). 수행자 수가 적어 점수의 신뢰구간이 넓어지므로 보고서에 명시한다. 신청서의 "51명" 표현은 수정·확인이 필요하다.
- 정정(같은 날, Training 단어 라벨 직접 집계): Training 수행자 ID는 **17개**(REAL01~16과 REAL25)이고, 수행자당 항목 수는 최소 275(REAL25로 추정, 약 55단어) ~ 최대 15,000(3,000단어 × 5시점). 정면(F) 라벨 3,000개 표본에서 빈 라벨 0, 다중 구간 0, 단어 구간 길이 중앙값 1.50초(최소 0.39, 최대 4.14). 따라서 위의 "Training 16명"은 틀렸고, 단어 데이터 전체 수행자는 REAL01~18과 25로 **19개 ID**다(REAL25는 단어 수가 적어 학습·시험 균형에 쓰기 어려움).
- 무효 표시: 위 "Training 수행자는 REAL01~16(16명)" 서술은 무효(정정 참조). 또 `plan.md`의 분할 계획과 `data-sources.md`의 받을 파일 판단은 이 결과로 갱신 필요.
- 추가(같은 날): 사용자가 "51명"은 두 데이터셋 중 다른 하나(114 재난)일 수 있다고 알려 줌. 기각은 004 단어 데이터에 한정하고, 114의 수행자 수는 114 라벨(형태소 VL, 이미 보유)로 확인할 예정.

### T-004 | 2026-10-18 | 사전 | [유재준]
- 가설: 신청서의 "수행자 51명(검증 데이터 기준)"은 114 재난 안전 수어 데이터의 검증 라벨에서 온 숫자다(사용자 제보).
- 시도: 114 Validation 형태소 JSON 7z(이미 보유)의 파일 이름 20,091개를 집계. 파일 이름 끝 토큰(`…_TW숫자.json`, `…_KU숫자.json`, `…_CROWD숫자.json`)을 수행자 구분자로 해석(잘못된 가정, 아래 판정). 압축은 풀지 않고 목록만 읽음.
- 결과: `1.tact_morpheme` JSON 12,750개에 서로 다른 토큰 **50개**(TW 38 + KU 12). `2.untact_morpheme` JSON 7,341개는 모두 `CROWD` 접두(번호가 파일마다 다름, 크라우드 참여자 번호로 보이며 수행자 수로 세지 않음). 수행자당 파일 수는 최소 3개, 최대 1,018개로 크게 치우침. [실데이터, 파일 이름 기준]
- 판정: **무효(2026-10-18 정정).** 이 집계는 "파일 이름 토큰 = 수행자"를 전제로 했는데, 이 프로젝트의 지난 세션 기록(`docs/sign-language/키포인트-설계-기록-2026-09-20.md` §6.2, `HANDOVER.md` §8)이 이 가정을 이미 반증했다(같은 수행자가 여러 토큰을 쓰고 한 토큰에 여러 수행자가 있음). 지난 기록의 올바른 방법(형태소 JSON 안 `metadata.signer.id`)으로는 Validation 수행자가 **51명(스튜디오 TW·KU 40명 + CROWD 11명)** 이다. 위 결과의 "50개"는 토큰 개수이고 수행자 수가 아니다. 51과 비슷하게 나온 것은 우연이다. 신청서의 "51명"은 636(재난) 검증 데이터의 `signer.id` 기준으로 맞다.
- 다음: 이 데이터(114 재난, 문장 단위)는 향후 과제(문장 인식)에서 수행자 독립 분할에 쓸 수 있다. 단어 인식기(004 단어)는 약 18명 기준으로 분할한다(T-002).
- 무효 표시: **이 항목 전체가 무효**(위 판정 참조). 이 항목을 근거로 한 서술은 없다. 단 T-002의 "신청서 51명은 004 단어 데이터에 없다"는 결론은 이와 무관하게 유효하다(단어 데이터는 파일 이름 `REALxx`로 수행자를 구분하며 Validation에 2개, 지난 기록과도 일치).
- 교훈: 작업 전에 `docs/sign-language/HANDOVER.md`를 먼저 읽었어야 했다. 이 폴더는 이름 검색(`*수어*`)에 안 걸려 처음에 찾지 못했다.
