### T-001 | 2026-10-18 | 사전 | [유재준]
- 가설: AI-Hub API 다운로드와 분할 파일 병합이 Windows(Git Bash)에서 WSL 없이 된다.
- 시도: `aihubshell -mode d -datasetkey 103 -filekey 39478`(004 Validation 단어 라벨, 14MB). 키는 환경변수에서 읽음. 실행 위치 `D:\sign-language-data\downloads\test-39478`.
- 결과: HTTP 200, 다운로드·tar 해제·병합 성공, 소요 3초(약 9.2MB/s, 표본 1개). 병합된 zip이 정상으로 열림. [실데이터, 표본 1개]
- 판정: 채택. 속도는 표본이 작아 참고값이다. 117GB는 단순 계산으로 약 3.5시간이지만 실제로는 큰 파일에서 다시 재야 한다.
- 다음: 이어받기 동작 확인, 큰 파일 속도 측정.
- 무효 표시: 없음

### T-002 | 2026-10-18 | 사전 | [유재준]
- 가설: 신청서가 근거로 든 "수행자 51명(검증 데이터 기준)"으로 단어 데이터에서 수행자 독립 분할을 할 수 있다.
- 시도: 받은 004 Validation 단어 라벨 zip의 파일 이름에서 수행자·시점·단어 번호를 집계(30,000항목).
- 결과: Validation 단어 데이터의 수행자는 **2명(REAL17, REAL18)**. 시점은 D·F·L·R·U 5개가 각 5,998개, 단어 번호 3,000종(0001~3000). Training 단어 라벨의 항목 수 240,000 = 16명 × 3,000단어 × 5시점으로 계산이 맞아 Training 수행자는 REAL01~16(16명)으로 보인다. 단어 데이터 전체 수행자는 약 18명이다. [실데이터]
- 판정: 가설 기각. "51명"이 어느 데이터를 가리키는지(예: 문장 데이터나 114 재난 데이터)는 확인하지 못했다.
- 다음: 수행자 독립 분할을 약 18명 안에서 설계한다(예: 학습 12 / 검증 3 / 시험 3명 단위). 수행자 수가 적어 점수의 신뢰구간이 넓어지므로 보고서에 명시한다. 신청서의 "51명" 표현은 수정·확인이 필요하다.
- 무효 표시: 없음. 단 `plan.md`의 분할 계획과 `data-sources.md`의 받을 파일 판단은 이 결과로 갱신 필요.
- 추가(같은 날): 사용자가 "51명"은 두 데이터셋 중 다른 하나(114 재난)일 수 있다고 알려 줌. 기각은 004 단어 데이터에 한정하고, 114의 수행자 수는 114 라벨(형태소 VL, 이미 보유)로 확인할 예정.

### T-003 | 2026-10-18 | 사전 | [유재준]

- 시도: 14MB 파일(키 39478)에 `curl -r 0-1023`으로 범위 요청.
- 결과: HTTP 200과 함께 파일 전체(14,435,840B)를 다시 보냄. 범위 요청을 무시함. [실데이터]

- 다음: 큰 파일(117GB)은 마지막에 받고, 작은 파일(30GB)부터 받아 손실 위험을 줄인다. 다운로드 중 노트북이 절전으로 들어가면 끊길 수 있어 전원·절전 상태를 유지한다.
- 무효 표시: 없음

### T-004 | 2026-10-18 | 사전 | [유재준]
- 가설: 신청서의 "수행자 51명(검증 데이터 기준)"은 114 재난 안전 수어 데이터의 검증 라벨에서 온 숫자다(사용자 제보).
- 시도: 114 Validation 형태소 JSON 7z(이미 보유)의 파일 이름 20,091개를 집계. 파일 이름 끝 토큰(`..._TW07.json`, `..._KU12.json`, `..._CROWD1076653.json`)을 수행자 구분자로 해석. 압축은 풀지 않고 목록만 읽음.
- 결과: `1.tact_morpheme` JSON 12,750개에 서로 다른 토큰 **50개**(TW 38 + KU 12). `2.untact_morpheme` JSON 7,341개는 모두 `CROWD` 접두(번호가 파일마다 다름, 크라우드 참여자 번호로 보이며 수행자 수로 세지 않음). 수행자당 파일 수는 최소 3개, 최대 1,018개로 크게 치우침. [실데이터, 파일 이름 기준]
- 판정: 가설 대체로 지지. tact 수행자 50명 + CROWD 1그룹 = 51로 읽을 수 있으나, 이 "51"의 계산 방식은 신청서 작성 당시 기준을 확인하지 못해 확정하지 않는다. 신청서의 "수행자별 파일 수가 크게 치우쳐 있어 균형을 고려" 서술과는 일치한다.
- 다음: 이 데이터(114 재난, 문장 단위)는 향후 과제(문장 인식)에서 수행자 독립 분할에 쓸 수 있다. 단어 인식기(004 단어)는 약 18명 기준으로 분할한다(T-002).
- 무효 표시: 없음. 수행자 구분을 파일 이름 토큰으로 한 것이므로, 같은 사람이 다른 토큰을 썼는지는 확인하지 못했다.
