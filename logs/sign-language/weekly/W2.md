# 2~3주차 주별활동보고서 초안

> 근거: `trials.md` T-019~T-037, `constraints.md`. 수치는 결과 json과 실행 로그에서 옮겼다. **지표 이름을 반드시 함께 적는다**(macro-F1과 정확도를 섞어 적은 기록이 있었음, T-036 정정). 제출 양식(hwp)에 옮길 때 날짜·장소·참석자를 채운다.

## 1. 목표 (신청서 2~3주차)
수행자 18명 정식 비교, 어휘 크기 영향, 남은 오류 분석과 개선 시도, 최종 모델 제작. 웹·실시간 입력은 사용자 결정으로 뒤로 미룸.

## 2. 결과

### 어휘 크기 (TCN, 시험 macro-F1, T-024)
50개 0.984 · 100개 0.989 · 200개 0.986 · 300개 0.978. 300개(시드 4개, T-036)는 macro-F1 0.979, 정확도 0.980.

### 수행자 14 분석 (T-022, T-029~T-032)
- 손을 18명 중 가장 높이 쓰고, 오류가 특정 단어 12개(그중 10개가 숫자)에 몰린 체계적 오류.
- 한국수어사전의 수형 설명과 대조하고 약지 접힘 지표로 측정한 결과, 14번의 80은 정당한 수어(약지 접힘)로 보임 → 문제는 모델 쪽.
- 손 높이·깊이·접힘 채널 어느 것으로도 해결되지 않음. 사람이 영상을 보고 확인하는 일은 보류(사용자 결정).

### 화면비 대응 (T-035)
입력 프레임을 16:9 틀에 넣고 남는 곳을 검게 채움(레터박스). 원본 영상을 잘라 흉내 낸 결과(수행자 3명 × 100클립, 정확도):

| 입력 | 레터박스 있음 | 레터박스 없음 |
|---|---|---|
| 핸드폰 세로 9:16 | 1.000 | **0.400** |
| 4:3 | 0.993 | 0.953 |
| (원본 16:9) | 0.993 | - |

→ 재학습 없이 핸드폰 세로·가로 지원. 실제 핸드폰 영상(구도·해상도 차이)은 미확인.

### 최종 모델 (T-037)
TCN, 클래스 300, 입력 243차원(몸 기준 좌표 106 + 손 상대 좌표 84 + 마스크 53), 수행자 18명 전부, 51에폭. 파일은 D 드라이브에만 보관(AI-Hub 데이터 파생물). 기대 성능은 교차 검증 값(정확도 0.980)을 인용한다.

## 3. 제약과 극복 (이번 주)
- 자리를 비우면 학습이 5~7배 느려짐(Windows 효율 모드) → 프로세스 단위 제외 요청 (C-15)
- 화면비에 따라 손 모양이 찌그러짐 → 레터박스 (C-16)
- 효과 없던 방법: 위 표의 기각 7건, 절전·충전으로 밤샘 작업 유지
