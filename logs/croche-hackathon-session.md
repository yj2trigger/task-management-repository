## 5단계: 실패와 성능

### 5-1. 끊김 상황별 대응

| 끊김 | 대응 | 이유 |
|---|---|---|
| Croche 네트워크 실패 | 템플릿 말 + 0층만 | 1층 비동기 (고양이 멈추지 않음) |
| 창 정보 읽기 실패 | L1(테두리)만 사용 | 다층 발판 찾기 (우아한 degradation) |
| DB 저장 실패 | 메모리만 사용, 저장 안 함 | 휘발성 상태는 메모리 (설계) |
| 관찰기 크래시 | 0층만 돌고 적응 안 함 | 독립적 책임 (AD-16) |

### 5-2. 성능 예산

| 상태 | CPU | 메모리 | FPS | 측정 |
|---|---|---|---|---|
| 평상시 | **2%** | 250MB | 10fps | 앉아 있을 때 |
| 걷는 중 | 3% | 250MB | 30fps | 이동 중 |
| 최대 (창 많음) | **4%** | 300MB | 30fps | VS Code+Chrome+음악 1시간 |
| 자리 비움 | 0.2% | 메모리 | 0fps | 입력 5분 없을 때 |

**기준 PC:** 팀원 노트북 (사양 확정 필요)

## 심사 대비 Q&A

| Q | A | 기준 |
|---|---|---|
| 왜 두 층? | Croche 대기 중에도 고양이 이동 (0층은 독립) | ③ 안정성 |
| 왜 메뉴? | Croche 오류 → 고양이 에러 방지 | ③ 안정성 |

| 해석 상태는 왜 메모리? | 매 초 바뀜 + 성능 2% | ⑤ 경제성 |
| 3일에 뭘 보여주나? | 핵심 흐름 + 대시보드 (학습 과정) | ③ 완성도 |
| 왜 Electron? | 파일 열기 + 창 정보 + JS 가능 | ① 문제 정의 |
